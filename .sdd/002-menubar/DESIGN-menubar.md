## 1. 一句话

菜单栏里常驻一个 cc-moss 图标：一眼看到哪个会话在忙、哪个在等你、哪个断了；点一下就在你的终端里打开它；
重启之后它会提醒你「有 3 个会话断了」，点一下全部找回。

## 2. 已定的假设

| # | 假设 | 理由 |
|---|------|------|
| A1 | 用 **Swift + SwiftUI**（`MenuBarExtra` 窗口样式），最低 **macOS 14** | 「原生」最直接的做法；SwiftUI 14 起有 `@Observable`，`SMAppService` 做开机自启 |
| A2 | 代码放本仓 `apps/macos/`，Swift Package 构建（不建 Xcode 工程），CI 加一个 macOS 任务跑 `swift build` + `swift test` | 和 CLI 同仓同版本，`ls --json` 契约改动一个 PR 两边一起改 |
| A3 | App 只调用 `cc-moss`：读用 `ls --json`，写用 `restore` `note` `close` `new --detach`；不直接打开 SQLite | 单一写入方；JSON 有版本号、向后兼容，SQLite 表结构不是公开契约 |
| A4 | 刷新：监听状态目录里 `registry.db*` 的变化（钩子每次写都会触发），合并 1 秒内的变化后刷新一次；另每 60 秒兜底刷新一次（用来发现进程已死的会话）；打开面板时立即刷新 | 实测一次 `ls --json` 0.2 秒；按事件刷新比固定轮询省电 |
| A5 | 「打开会话」= 在你选的终端里开一个新窗口执行 `cc-moss attach <名字>`。设置里有「终端」一项，列出本机装了的、我们支持的终端：系统自带的**终端（Terminal）为默认**，**推荐 Ghostty**（未安装时显示推荐与下载入口），另支持 iTerm2、WezTerm、Kitty、Alacritty；Warp、VS Code 内置终端等没有稳定外部接口的，提供「复制命令」 | 用户 2026-10-16：默认系统终端、推荐 Ghostty、可配置多种终端 |
| A6 | 不在 tmux 里的会话照样列出，标注「不在 tmux 里，没法从这里打开」，不给打开按钮 | `attach` 对它们本来就做不到 |
| A7 | 图标用定稿的 Continuum 无限环（模板图，跟随菜单栏深浅色），**用动画表达动态**：有会话在忙 = 环上一个光点缓缓流动；需要你确认 = 轻轻跳动并带强调色；在等你 = 静止加小圆点；有会话断了 = 琥珀色静止。优先级：需要你确认 > 断了 > 在忙 > 在等你。系统打开「减少动态效果」时只换颜色不动；屏幕休眠时停帧 | 一眼看状态是 D1 的核心；动画要克制，不抢注意力 |
| A8 | 开机自启默认**开**（首次启动时问一次）；开机时如果发现有中断的会话，发一条系统通知「有 N 个会话断了」，点通知打开面板 | D2：重启后主动提醒，但恢复仍由用户点（R8） |
| A9 | 会话事件发到系统通知中心，按类型开关：**需要你确认**（权限请求、提问）默认开；**会话断了** 默认开；**这一轮做完了，在等你** 默认关（每轮都会触发，太吵）；**找回完成** 默认开。点通知 = 在终端里打开该会话 | 用户追加需求：各种 session 事件经通知中心通知 |
| A13 | **会话事件流**：钩子把每个有意义的变化记成一条事件（新会话、开始干活、这一轮做完、需要你确认、断了、结束、找回、改名），存在登记表的 `events` 表里（只保留最近 7 天）；`cc-moss events --json --since <序号>` 按序号增量读。App 收到「登记表变了」就去拉新事件。快照（`ls --json`）负责「现在是什么样」，事件负责「刚发生了什么」 | 通知和动画需要的是「变化」，对比快照会漏掉 1 秒内一闪而过的变化；003–005 都建在这条流上 |
| A14 | 「需要你确认」的来源：新注册 `Notification` 钩子（`permission_prompt`、`elicitation_dialog`、`agent_needs_input`），置会话的 `attention`；下一次 `PostToolUse`/`Stop`/`UserPromptSubmit` 时清除。`ls --json` 加 `attention` 字段 | Claude Code 文档：Notification 在权限提示等约 6 秒后触发，不能阻塞，只做记录正合适；终端里点了同意没有专门事件，只能靠工具跑完来推断 |
| A15 | 新增钩子要用户重跑一次 `cc-moss setup`（`doctor` 会提示缺哪个），升级时 `cc-moss update` 结束后主动提醒；不偷偷改 `settings.json` | 沿用 Stage 1「改用户配置先给看、再确认」 |
| A16 | 本迭代**不拦截**任何确认：钩子只记录、立即返回，不影响 Claude Code 的正常提示。代办确认是 004-pet-approve 的事 | 拦截涉及安全（误点同意即执行命令），要单独设计与评审 |
| A17 | **视觉与交互参照 Raycast**（用户 2026-10-16 指定，本机在用）：面板顶部是大号无边框搜索框；列表按项目分节，节标题是小号灰字；行左侧状态图标、标题、灰色副标题，右侧附件（状态标签、时间）；选中行是圆角高亮块；底部动作栏左侧显示当前上下文，右侧是主动作「打开 ↵」与「更多 ⌘K」，⌘K 弹出动作面板（每个动作带快捷键提示）；半透明毛玻璃背景、圆角、细分隔线。键盘优先，鼠标同样顺手 | 用户认可的交互标杆；与 `t` 的「打字即搜索、方向键、回车」同一套肌肉记忆 |
| A18 | **状态栏条目参照 iStat Menus**（用户 2026-10-16：「最佳的状态栏 UI 交互」）：菜单栏条目本身可在图标旁显示紧凑的实时信息（如需要你的会话数），显示方式可选（仅图标 / 图标 + 数字）；下拉面板顶部是仪表盘式的摘要条（在忙 / 在等你 / 已中断的计数，点一下即按该状态筛选），细节在悬停时展开。分工：状态栏条目与摘要条学 iStat Menus，列表、搜索、键盘与动作栏学 Raycast（A17） | 两个标杆各取所长 |
| A19 | **自定义别名改为原生命令，不再写 shell 函数**（用户 2026-10-16 提议）：采用 BusyBox 式「一个程序多个名字」——别名是指向 `cc-moss` 的符号链接，放在 `~/.local/bin/`（`cc-moss install` 已保证它在 PATH 上）；`cc-moss` 启动时看自己被叫成什么名字（`argv[0]`），在 `config.toml` 的 `[aliases]` 里查到对应的命令再执行，用户敲的参数接在后面。例：`[aliases] t = "pick"`、`mycc = "new --dangerously-skip-permissions"` → `mycc 登录页` 等于 `cc-moss new --dangerously-skip-permissions 登录页`。管理：`cc-moss alias ls / add <名字> <命令> / rm <名字>`；App 的设置页经这几条命令增删改（单一写入方不变）。`t` 也迁到这套机制，zsh 里的 `function t` 退役 | 任何 shell（zsh、bash、fish）、脚本、新开的终端都直接可用；改完立即生效，不用 `source`；不再往用户的 rc 文件里写函数 |
| A20 | **设置窗口参照 Raycast 设置**（用户 2026-10-16 指定，并要求对照本机 Raycast 的实际 UI）：系统侧边栏（`NavigationSplitView`，macOS 26 上是 Liquid Glass 浮动侧边栏，窗口按钮与「搜索设置…」在栏内），条目带彩色图标方块，选中为中性灰；右侧分组行。度量取自本机 Raycast 的设置页样式表（只取数值作参照，不复制其任何图标与图片）：分组底色为前景色 2.5%、无边框、圆角 12；行最小高度 46、内边距 12；行间分隔线为前景色 5%、左右各缩进 12；分组标题高 32、左缩进 12；分组间距 16。标签页（侧栏条目）：**通用**（开机自动打开、唤出面板的全局快捷键、界面语言、默认终端、cc-moss 程序位置与版本/检查更新）、**通知**、**别名**（Raycast 扩展页式表格）、**关于**。改动即时生效，没有「保存」按钮；条目随功能一起加入，不放空页 | 用户认可的设置交互标杆；系统侧边栏自动获得 macOS 当代材质 |
| A21 | **图标语言**（用户 2026-10-16：「精美的 icon 设计以及在合适的 Apple Design 设计哲学里面，适当的用 icon 替换文字」）：一套统一的 SF Symbols 词汇（代码里的 `Icons`），状态、动作、元信息都有固定图标，不临时挑。按 Apple 的做法取舍：含义一眼可辨的地方**用图标替换文字**（状态图块、worktree、不在 tmux、筛选里未选中的段只显示图标 + 数字）；**动作保留文字**（主动作、⌘K 菜单都是图标 + 文字，同 macOS 菜单）；**不放装饰性图标**（与旁边文字重复的，如时间前的时钟）；**纯图标元素必须有悬停提示和 VoiceOver 标签** | 视觉安静、信息密度高；可读性靠一致的词汇和提示兜底 |
| A22 | **首次启动引导**（用户 2026-10-16：Raycast 有非常精美的启动引导，我们也需要，放到正式版发布前做）：首次打开 App 时的欢迎窗口，几步讲清楚 cc-moss 能做什么、检查并引导装好 CLI 与钩子、开机自动打开与通知权限的授权、选择默认终端；动画与视觉同面板 | 第一印象；把 `cc-moss install` 的步骤搬进图形界面 |
| A23 | **一件事只提醒一次、只在一处**（用户 2026-10-16：系统通知和宠物通知应该互斥，否则会重复）：每个事件由「提醒路由」决定唯一的出口。设置「提醒方式」：**自动**（默认：小莫在桌面上可见时由它冒气泡；它没开、被收起、全屏或演示时自动退场，就改走系统通知中心）/ **只用通知中心** / **只用小莫**。已经交给其中一处的事件，不会因为另一处之后才可用而再补发；面板开着时，面板里已能看到的事不再提醒；系统通知和气泡的主动作相同（打开会话 / 找回）。T2.3 通知中心与 T3.3 气泡共用同一个 MossKit `AlertRouter`（纯逻辑，可单测） | 重复提醒是最快把人烦走的方式；路由集中一处，规则才不会两边各写一套而漂移 |
| A24 | **菜单栏动态效果可关**（用户 2026-10-16：设置中可以选择不开启状态栏动态效果以节省资源）：设置 › 通用 › 菜单栏 ›「动态效果」，默认开；关掉后图标只在状态变化时换一张静态图（0% CPU），系统「减少动态效果」打开时同样静止 | 把资源取舍交给用户，并在说明里写清代价 |
| A10 | 中英双语，跟随系统语言，文案沿用 CLI 的语气（口语、友好、带点幽默，不用 emoji）。每条界面文字都成对写（`L.t(英, 中)`），没有只写一种语言的文字。设置里的「界面语言」（跟随系统 / 中文 / English）与 CLI 共用 `config.toml` 的 `[ui] language`（经 CLI 写入），切换后 App 立即生效、`t` 下次打开生效 | 与 Stage 1 一致；用户 2026-10-16 再次强调中英国际化 |
| A11 | App 名 `cc-moss`（Dock 不显示，只在菜单栏），Bundle ID `io.github.larrykoo711.cc-moss` | 与项目同名；不用私人域名 |
| A12 | **随 cc-moss 一起发**（Q1 按建议执行，用户未提异议；改为签名公证 + cask 是后加项，不推翻本条）：同一个版本号、同一个 Release；Homebrew 公式在 macOS 上把 App 一起装进来，`cc-moss install` 问你要不要放进「应用程序」，`cc-moss update` 升级时 App 一起升 | 不新增分发渠道；CLI 与 App 永远同版本，`ls --json` 不会对不上 |

## 4. 面板长相（草图）

```text
 ┌───────────────────────────────────────────┐
 │  搜索会话…                                 │
 │  ! 有 2 个会话断了             [全部找回]   │
 │                                           │
 │  projects                                 │
 │   ● term-kit           在忙   · 刚刚       │
 │     开始 Ship Stage2                       │
 │   ○ api-review         在等你 · 5 分钟前    │
 │     这个接口的错误码对一下                  │
 │  billing  · worktree                      │
 │   ◌ fix-invoice        已中断 · 昨天  [找回] │
 │     便条：停在对账脚本                      │
 │  ───────────────────────────────────────  │
 │  新会话…                 设置    退出      │
 └───────────────────────────────────────────┘
```

- 点会话行 = 在终端里打开；行尾「⋯」= 写便条 / 不再提醒；已中断的行点击 = 找回并打开
- 键盘：打开面板即可打字搜索，上下选，回车打开，Esc 关闭（与 `t` 一致，不需要记别的）
- 新会话：选目录（默认最近用过的项目）+ 起名，建好后在终端里打开

## 5. 找到 cc-moss

按顺序找：设置里手动指定的路径 → `/opt/homebrew/bin/cc-moss` → `/usr/local/bin/cc-moss` →
`~/.cargo/bin/cc-moss` → `~/.local/bin/cc-moss`。找不到时面板只显示一张引导卡（怎么安装，一条命令）。
版本低于 App 要求时同样提示升级。

## 6. 打开终端

| 终端 | 做法 |
|------|------|
| Ghostty | `new surface configuration` 设 `command` 为 `cc-moss attach <名字>`，`new window with configuration` |
| iTerm2 | `create window with default profile command "…"` |
| Terminal | `do script "…"`，再 `activate` |

- 命令里的名字一律按 shell 单引号转义；脚本经 `NSAppleScript` 执行，首次会触发系统的「自动化」授权弹窗，
  被拒时给出去系统设置的引导
- 该会话已经在某个终端窗口里打开时，仍新开一个窗口（tmux 允许多个客户端）；「切到已有窗口」留作后续

## 7. 测试策略

- `moss-kit`：JSON 解码（含字段缺失、schema 不认识）、状态计算、分组排序、过滤、路径探测、
  各终端生成的脚本与转义（表驱动）。命令执行层可注入假实现，不碰真实 `cc-moss`
- `cli-contract`：Rust 侧给新字段加测试，锁定 schema 1 只增不改
- UI：SwiftUI 预览 + 演示数据渲染截图；真机走查（human-feel）覆盖图标三态、打开、找回、新会话
- 端到端：用独立状态目录（`CC_MOSS_STATE_DIR`）和独立 tmux socket 跑演示数据，不碰真实会话
