# T2.1-event-stream — 会话事件流与「需要你确认」

- Source: `DESIGN-menubar.md` §1.1、A13–A16；PLAN T2.1；用户 2026-10-16「通过状态栏的图标动画来展示动态，以及有各种 session 事件通过通知中心来通知」
- arch_level: yes
- depends_on: []
- verify_layers: [unit, integration, e2e, perf]
- risk: hot-path
- mutations:
  - point: 事件序号不单调（按时间而非自增 id 读取）  red: events::since_returns_only_newer_in_order
  - point: PostToolUse 不清 attention  red: state_machine::post_tool_use_clears_attention

## 目标

钩子把会话里每个有意义的变化记成一条事件；`cc-moss events --json --since <序号>` 按序增量读出。会话需要你确认
（权限请求、提问）时 `ls --json` 的 `attention` 字段有值，确认之后自动清掉。这是图标动画、通知中心以及以后桌面宠物的共同地基。

## Scope（YAGNI）

**In**
- 登记表：新建 `events` 表（`seq INTEGER PRIMARY KEY AUTOINCREMENT, slot_id, kind, detail TEXT(JSON), at INTEGER`）与 `slots.attention` 列。
  **不升 `user_version`**：只增表和列，0.1.x 仍能读写（它们只是不写事件）；`ensure_columns` 式就地补齐
- 事件种类（`kind`）与触发点（都在 `apply_with` 的同一事务里写，保证与状态一致）：

  | kind | 触发 | detail |
  |------|------|--------|
  | `started` | SessionStart startup/resume 新建或接回槽位 | `{source}` |
  | `working` | UserPromptSubmit（busy 0→1） | `{}`（不带提示词全文） |
  | `finished` | Stop（busy 1→0） | `{}` |
  | `needs_you` | Notification `permission_prompt` / `elicitation_dialog` / `elicitation_url_dialog` / `agent_needs_input` | `{reason: permission\|question\|input, message}`（message 截断 200 字符） |
  | `renamed` | 名字变化 | `{from, to}` |
  | `ended` | SessionEnd 用户主动结束 | `{reason}` |
  | `interrupted` | SessionEnd 异常，或对账发现进程已不在（每次中断只记一次） | `{reason}` |
  | `restored` | `restore` 拉起成功 | `{}` |
  | `closed` | `cc-moss close` | `{}` |

- 新钩子：`Notification`（不设 matcher，类型在代码里分流；其余类型忽略）、`PostToolUse`（matcher `*`）。
  `HookKind` 增加两项；`setup` 补写、`--uninstall` 移除、`doctor` 报缺；钩子仍永远 exit 0、不写 stdout
- `attention`：`needs_you` 时置为 reason；`PostToolUse`、`Stop`、`UserPromptSubmit`、`SessionEnd`、`SessionStart` 时清空。
  `PostToolUse` 走快速路径：只在该槽位 `attention` 非空时写库，不做进程存活预取
- `cc-moss events --json [--since N] [--limit 500]`：`{"schema":1,"events":[{seq,slot_id,name,kind,detail,at}],"last_seq":N}`；
  不跑对账（便宜）；`--since` 缺省返回最近 50 条
- 对账（`ls`/`pick` 打开时）为「进程已不在」的 running 槽位补记 `interrupted`（以该槽位最近一条事件是否已是 `interrupted` 去重）
- 清理：对账时删除 7 天前的事件（钩子路径不清理）
- `ls --json` 每会话加 `attention`（`null` 或 `"permission"`/`"question"`/`"input"`）
- 真机探针：用真实 Claude Code 在独立 tmux socket 里触发一次权限提示和一次提问，记录 Notification 的真实输入，补进 `notes/hook-probe-2.md`

**Out**
- 任何拦截或代答（A16，留给 004）；`PermissionRequest` 钩子不注册
- App 侧的消费（T2.2、T2.3）
- `idle_prompt`、`agent_completed`、额度相关的通知类型

## Notes / 开放问题 / 澄清日志

（实施中追加）

- 2026-10-16 真机探针（`notes/hook-probe-2.md`，Claude Code 2.1.301）：AskUserQuestion 发的也是 `permission_prompt`，
  message 与权限提示完全相同，Notification 里分不出来。实现按 Scope 映射，提问在 2.1.301 上显示为 `permission`；
  `question` 只来自 `elicitation_dialog`/`elicitation_url_dialog`。要区分需 PreToolUse，留给 004（开放问题）
- 自决：`events --json` 的 `at` 用 RFC 3339 字符串（与 `ls --json` 的时间字段同口径），库里存毫秒
- 自决：`last_seq` = 本次返回的最后一条；没有返回时为库中最大序号（空库 0），调用方原样传回 `--since` 即可续读
- 自决：不带 `--since` 时返回最近 min(50, `--limit`) 条，仍按序号升序
- 自决：`renamed` 不记新槽位出生时带的名字（属于 `started`）；之后任何变化（含从无名到有名、从会话记录补名）都记
- 自决：`idle_prompt`、`agent_completed`、`auth_success` 静默忽略；其余未知类型写一行 hook.log 后忽略
- 自决：PostToolUse 快速路径按 session_id 清 attention（不取进程启动时间，不区分同一对话的两个进程）；
  也不再为它记「缺 CLAUDE_PID」的警告，避免每次工具调用刷日志
- 自决：对账补记的 `interrupted` 的 detail 为 `{"reason":"process-gone"}`；补记时一并清掉 attention；
  `ls --json` 只对 running 会话输出 attention
- 自决：`doctor` 在「部分钩子在、部分缺」时报「少了 N 个钩子（事件名）」，全缺仍报「没装或已过期」
- 风险：升级后首次对账会给库里「进程早已不在、仍标 running」的旧槽位各补一条 `interrupted`（`at` 为当下），
  App 首次拉取时需按需忽略或只从当前 `last_seq` 开始
- 未做：A15 提到的「`cc-moss update` 结束后主动提醒补钩子」不在本 spec Scope 内，未实现
