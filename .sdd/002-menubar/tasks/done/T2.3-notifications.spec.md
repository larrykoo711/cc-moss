## 目标

会话发生值得告诉你的事时，只在一个地方提醒你一次：小莫在桌面上可见时由它负责（T3.3 实现它的表达），否则发到系统通知中心；
点通知 = 打开那个会话（或找回）。通知按类型可开关，同一会话短时间内的重复事件合并。

## Scope（YAGNI）

**In**
- MossKit `AlertRouter`（纯逻辑，可单测，T3.3 复用）：输入事件 + 环境（提醒方式设置、小莫是否可见、面板是否打开、勿扰）→ 出口 `.notification` / `.pet` / `.none`；已路由过的事件 id 不再路由（不补发）；面板打开时面板里看得到的不提醒
- 事件来源：`events --json --since`（App 首次启动从当前 `last_seq` 开始，不回放旧事件，见 T2.1 澄清）；随快照刷新拉增量
- 类型与默认（A9）：需要你确认 开、会话断了 开、这一轮做完了 关、找回完成 开；合并窗口 30 秒（同会话同类型）
- `UNUserNotificationCenter`：首次需要时请求授权；被拒时设置页给出引导（打开系统设置 › 通知）；通知带动作「打开」/「找回」，点击正文 = 主动作
- 设置 › 新增侧栏「通知」页：提醒方式（自动 / 只用通知中心 / 只用小莫）+ 四个类型开关 + 授权状态；用 SlidingPicker 与 CardRow
- 小莫这一侧：本任务只向 `PetController` 报告「这件事归你」（T3.3 才做气泡）；小莫没开时一律走通知中心

**Out**
- 小莫的气泡与互动模式（T3.3）；开机提醒（T2.4）

## Notes / 开放问题 / 澄清日志

（实施中追加）

- 2026-10-16 实施自决：
  - 事件读取只留一处：`EventFeed`（App 级，跟着快照刷新拉增量）取代 `PetController` 自己的读取；小莫从 feed 收 `restored` 做开心动作，通知也从同一个 feed 来。游标逻辑放进 MossKit `EventCursor`（首页只定位，不回放）
  - 「小莫可见」= 已开启、窗口在、没被遮住（全屏）、屏幕没睡也没锁、没收到边上（A23「被收起」）。「只用小莫」在小莫开着但暂时看不见时仍归小莫；小莫没开时走通知中心
  - 勿扰沿用小莫右键菜单的勿扰（`petDoNotDisturbUntil`）：期间三种方式都不提醒（表情仍由快照驱动）。系统的专注模式由 macOS 自己处理
  - 面板开着时一律不提醒（面板能看到所有会话的状态）；被这条或勿扰压下的事件也算「已路由」，之后不补发
  - 类型开关与 30 秒合并在路由之前，对通知和小莫同样生效；合并以事件的 `at` 计时（缺时用到达时间），被合并的直接丢弃
  - 授权：不在启动时问，第一次真要发通知时问一次（同一次运行不重复问）；设置页可提前「允许通知」；被拒给「打开系统设置」；不在「应用程序」目录时显示「这里用不了」并说明原因
  - 「找回」动作：T1.3 的一键找回尚未合入，点「找回」先打开面板并选中该会话（面板主动作即找回）；T1.3 合入后可在 `AlertCenter.perform` 一处改为直接找回
  - `MossKit.Alert` 与 SwiftUI 的 `Alert` 重名，类型名用 `SessionAlert`
