## 目标

断了的会话在面板里一键找回：顶部横幅「有 N 个会话断了 · 全部找回」，单行「找回」，找回后可直接在终端打开。
很久以前断开的会话（默认 7 天前）折叠成「更早断开的 N 个」，不与刚断开的混在一起；找不回的（空会话、目录没了）说明原因。

## Scope（YAGNI）

**In**
- CLI：`cc-moss restore --yes --json [name…]` 输出每个会话的结果 `{schema:1, results:[{id,name,ok,reason?}]}`（reason 用稳定的代码：`empty`、`missing_dir`、`exited_at_once`、`tmux_failed`、`already_running`），文字输出不变
- MossKit `RestoreGroups`：把已中断会话分成「最近」与「更早」（按 `last_active_at`，阈值 7 天，可注入时钟）
- MossKit `RestoreFlow`：命令拼装、JSON 解码、进行中状态（同一会话或全部进行中时再点无效）、失败原样带出 CLI 的话
- 面板：
  - 有最近断开的会话时，列表顶部一条横幅：图标 + 「有 N 个会话断了」+ 主按钮「全部找回」；找回中显示进度，完成后变成「找回了 N 个」并在 3 秒后收起
  - 已中断行：悬停按钮与主动作从「复制找回命令」改为「找回」；找回成功后该行变回在等你 / 在忙，并提供「打开」
  - 「更早断开的 N 个」折叠组：默认收起，展开后可逐个找回或「都不再提醒」（`cc-moss close`，需确认）
  - 找不回的行显示原因（空会话：「这个会话还没说过话，没什么可找回的」）与「不再提醒」
- 筛选栏「已中断」计数只算最近的；折叠组单独显示数量

**Out**
- 开机后自动提醒（T2.4）；自动找回（R8：永远由用户触发）

## Notes / 开放问题 / 澄清日志

（实施中追加）

- 2026-10-16 实施自决：
  - `--json` 只能配 `--yes`（`requires`），与 `--dry-run` 互斥；JSON 模式下失败也算结果，总是打印 JSON 并以 0 退出，命令本身出错（登记表打不开、名字不存在）才非 0
  - 结果在 `{id,name,ok,reason?}` 之外多一个 `message?`：CLI 的原话（已本地化），App 在拿不到稳定代码时原样展示（「失败原样带出 CLI 的话」）
  - 原因代码映射：`EmptySession`→`empty`、`MissingCwd`→`missing_dir`；`RestorePending`、`OpenElsewhere`、`Duplicate`、计划后被改动、按名字点了正在运行的会话 → `already_running`；`ensure_access`/`new_session` 失败 → `tmux_failed`；启动即退出 → `exited_at_once`
  - App 的「全部找回」按名字传入最近断开的那些（`restore --yes --json -- 名字…`），不传名字会连「更早」组一起找回；e2e `json_restores_all_after_a_crash` 用的正是这条命令
  - App 调 restore / close 用 `Session.target`（名字，否则完整对话 id）：`handle` 对无名会话给的是槽位 ULID，CLI 的 `resolve` 不认它（`attach` 同样受影响，见报告）
  - 找不回且再试也没用的（`empty`、`missing_dir`）行，主动作换成「不再提醒」，单个不二次确认；「更早」组的「都不再提醒」要二次确认
  - 最近 / 更早阈值按 `last_active_at` 与 7 天；`StateCounts.interrupted` 只算最近的，另有 `olderInterrupted`
  - 演示数据另起 `demo/restore.{zh,en}.json`（在原有之上加 3 个更早断开的会话），原演示数据不动
