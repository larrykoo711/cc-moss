## 目标

产出桌面宠物的设计档并经用户批准（G1）：它长什么样、会做哪些动作、怎么把会话事件演出来、什么时候说话、怎么跟人交互、
花多少资源。设计要为 004（宠物代办确认）与 005（语音对话）留好位置，但本阶段不做它们。

## Scope（YAGNI）

**In**
- 调研：Mac 上常驻小伙伴类产品与开源实现（窗口技术、动画形式、打扰控制），三档结论带出处
- 形象：基于 Continuum 无限环的原创角色（MOSS 的气质：安静、可靠、偶尔幽默），**自绘**，不得使用任何第三方受版权保护的形象或素材；给出 2–3 个方向的原型图（SwiftUI 绘制、离屏渲染为 PNG）供用户挑选
- 动作表：待机、在忙（思考）、需要你（招手）、断了（担心）、找回 / 完成（开心）、睡觉（勿扰），每个动作的时长、循环方式、帧数或参数化动画方案
- 事件 → 演出映射：基于 T2.1 的事件种类，什么事件做什么动作、要不要气泡、要不要说话；同类合并与节流
- 交互：拖动摆放、记住位置与所在屏幕、点击展开面板、右键菜单（勿扰一小时 / 今天、收起、设置）、全屏应用与演示时自动隐藏
- 窗口技术：透明无边框置顶 `NSPanel`、不抢焦点、所有桌面空间可见、鼠标穿透的区域
- 预算：空闲 CPU < 1%、内存 < 60MB、动画帧率上限；隐私（不读取会话内容以外的东西，播报只读事件里的短句）
- 给 004、005 留的接口：气泡里的按钮区、语音输入的入口位置
- 出图：一张交互原型（archify 或 HTML 原型），一张事件 → 动作的时序图

**Out**
- 实现（T3.2–T3.4）；代办确认与语音对话（004、005）
