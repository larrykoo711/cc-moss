## 目标

别名是 `~/.local/bin` 里指向 `cc-moss` 稳定入口的符号链接；`cc-moss` 被以别名调用时，在 `config.toml` 的 `[aliases]`
里查到对应的子命令再执行，用户参数接在后面。`cc-moss alias ls|add|rm` 管理；`t` 迁到这套机制；App 设置里有「别名」页可增删改。

## Scope（YAGNI）

**In**
- `config.toml`：`[aliases]` 表，`名字 = "子命令 参数…"`（按空白切分，支持单双引号成组，**不经 shell**）；只允许 cc-moss 自己的子命令（`hook` 除外）
- argv[0] 分派（`main.rs` 最先判断）：程序名不是 `cc-moss` 且在 `[aliases]` 里 → 展开后交给原有的命令解析；查不到 → 友好报错并提示 `cc-moss alias ls`
- `cc-moss alias ls [--json]`、`alias add <名字> <命令…> [--force]`、`alias rm <名字>`：
  - 名字只允许 `a-z0-9-_`，不能是 `cc-moss`
  - `add` 发现 PATH 上已有同名命令（不是我们的链接）时拒绝，`--force` 才覆盖（Q9）
  - 用用户登录 shell 查同名 alias / function（`$SHELL -ic 'type <名字>'`，2 秒超时），有则提示会被遮住（Q8），不阻止
  - 链接指向稳定入口：PATH 上找到的 `cc-moss`（如 `/opt/homebrew/bin/cc-moss`），不指向 `Cellar`（Q10）
  - 写 `config.toml` 只改 `[aliases]` 表，保留其余内容与注释（`toml_edit`）
- `t` 迁移：`setup` / `install` 默认建 `t = "pick"` 的链接；若 `.zshrc` 里有旧的 `cc-moss` 受管区块里的 `function t`，从区块里移除（只动受管区块）；`install --uninstall` 删掉全部别名链接
- `doctor`：列出别名、指出失效链接（可 `doctor --fix` 修复）、被遮住的别名、PATH 不含 `~/.local/bin` 的情况
- App 设置 › 新增侧栏「别名」：Raycast 扩展页式表格（搜索、名字 / 命令 / 状态三列、行内编辑、添加与删除），全部经 `cc-moss alias … --json` 读写

**Out**
- 自动迁移用户自己写的函数（Q8：只提示）；别名里的管道与 shell 语法

## 风险与回退

- 覆盖用户已有命令：默认拒绝，`--force` 才覆盖，且只覆盖指向我们自己的链接以外的情况需显式确认
- 回退：`cc-moss alias rm` 或 `install --uninstall`；旧的 `function t` 可由 `setup` 旧版本恢复
