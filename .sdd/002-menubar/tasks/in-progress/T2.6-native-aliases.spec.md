- Source: DESIGN A19、Q8–Q10（用户 2026-10-16 提议：别名在客户端设置里自定义，做成原生命令而非 shell 函数）；PLAN T2.6

- risk: logic

  - point: PATH 上已有同名命令时仍允许添加  red: aliases_cli::add_refuses_existing_command

## 目标

别名是 `~/.local/bin` 里指向 `cc-moss` 稳定入口的符号链接；`cc-moss` 被以别名调用时，在 `config.toml` 的 `[aliases]`
里查到对应的子命令再执行，用户参数接在后面。`cc-moss alias ls|add|rm` 管理；`t` 迁到这套机制；App 设置里有「别名」页可增删改。

## Scope（YAGNI）

**In**
- `config.toml`：`[aliases]` 表，`名字 = "子命令 参数…"`（按空白切分，支持单双引号成组，**不经 shell**）；只允许 cc-moss 自己的子命令（`hook` 除外）
- argv[0] 分派（`main.rs` 最先判断）：程序名不是 `cc-moss` 且在 `[aliases]` 里 → 展开后交给原有的命令解析；查不到 → 友好报错并提示 `cc-moss alias ls`
- `cc-moss alias ls [--json]`、`alias add <名字> <命令…> [--force]`、`alias rm <名字>`：
  - 名字只允许 `a-z0-9-_`，不能是 `cc-moss`
  - `add` 发现 PATH 上已有同名命令（不是我们的链接）时拒绝，`--force` 才覆盖（Q9）
  - 用用户登录 shell 查同名 alias / function（`$SHELL -ic 'type <名字>'`，2 秒超时），有则提示会被遮住（Q8），不阻止
  - 链接指向稳定入口：PATH 上找到的 `cc-moss`（如 `/opt/homebrew/bin/cc-moss`），不指向 `Cellar`（Q10）
  - 写 `config.toml` 只改 `[aliases]` 表，保留其余内容与注释（`toml_edit`）
- `t` 迁移：`setup` / `install` 默认建 `t = "pick"` 的链接；若 `.zshrc` 里有旧的 `cc-moss` 受管区块里的 `function t`，从区块里移除（只动受管区块）；`install --uninstall` 删掉全部别名链接
- `doctor`：列出别名、指出失效链接（可 `doctor --fix` 修复）、被遮住的别名、PATH 不含 `~/.local/bin` 的情况
- App 设置 › 新增侧栏「别名」：Raycast 扩展页式表格（搜索、名字 / 命令 / 状态三列、行内编辑、添加与删除），全部经 `cc-moss alias … --json` 读写

**Out**
- 自动迁移用户自己写的函数（Q8：只提示）；别名里的管道与 shell 语法

## Notes / 开放问题 / 澄清日志

（实施中追加）

- 2026-10-16 实施决定（agent）：
  - DESIGN A19 的示例 `mycc = "new --dangerously-skip-permissions"` 按现有 `new` 跑不通：`new` 只在 `--` 之后收 claude 参数，
    而 `new -- --x 登录页` 会把名字也当成 claude 参数。文档与帮助改用 `tn = "new"`、`tr = "restore --yes"`；
    想让每个新会话都带某个 claude 参数，用现成的 `[claude] default_args`。是否让 `new` 透传未知参数，留给控制者决定
  - `alias add` 只给一个参数时按整条命令文本读（App 走这条），多个参数时按词处理并按需加引号；`--force`/`--json` 写在名字前
  - `--force` 只用于「PATH 上别处已有同名命令」；`~/.local/bin` 里不是我们的文件（普通文件、指向别处的链接、目录）
    加 `--force` 也不替换（比 spec 的风险条更严）
  - 「我们的链接」= 目标文件名为 `cc-moss` 的符号链接；只有它会被替换或删除；替换先在旁边建临时链接再 rename，替换前再查一次
  - `install`/`setup` 写 `t = "pick"` 与链接都进同一个 diff 并先问；配置里已有 `t`（哪怕指向别的命令）就尊重用户；
    `--uninstall` 删掉所有别名链接与自己加的 `t = "pick"`（文件只剩它时整份删除），用户自己的别名留在配置里并提示
  - 程序名以 `cc-moss-`/`cc-moss.` 开头也视为本体（Release 包名），别名不能用这些名字
  - 遮挡检查一次 `$SHELL -ic` 跑完全部名字（名字先过 `a-z0-9-_` 校验再进脚本）；PATH 前面的同名程序也算遮挡
  - CI 的 Linux 测试任务加装 zsh，让 `works_in_bash_and_zsh` 在两种 shell 下都跑
- 2026-10-16 安全评审修复（agent）：
  - I1 回退到解析后的真实二进制；hooks 与链接共用 `aliases::stable_entry`（删掉 `settings_json::stable_exe`）
  - I2 `type` 输出只读 `<名字> is ` 之后的部分
  - I3 选择让 `setup` 也给 zsh 用户写 `.zshenv` 的 PATH 区块（进 diff、先问），而不是保留旧函数：只有一套机制，
    且区块只改 PATH、不输出任何东西；非 zsh 给一行提示。`setup --uninstall` 在 install 的 shell 区块不在时把它收回
  - `setup --uninstall` 只删 `t`；全部别名链接仍归 `install --uninstall`
  - 不在 add 时用 clap 校验整条命令：集成分支的 `launch_args::normalize_new` 在别名展开后才改写 `new` 的参数，
    这里提前校验会误拒用户选定的 `mycc = "new --dangerously-skip-permissions"`；运行时 clap 照样报清楚的用法错误
  - 示例别名 `tr` 改为 `tback`（与集成分支一致）
