## 目标

菜单栏的 Continuum 图标用动画表达会话动态：有会话在忙时环上一个光点缓缓流动；需要你确认时轻轻跳动并带强调色；
有会话断了显示琥珀色；只是在等你时静止加一个小圆点。图标旁可选显示紧凑数字。动画克制、省电。

## Scope（YAGNI）

**In**
- MossKit：`Snapshot` 解码 `attention`（T2.1 已输出）；`IconState` 由会话算出：`needsYou`（任一 running 会话 attention 非空）> `interrupted` > `working` > `waiting` > `idle`；`IconBadge` 给出紧凑数字（需要你的数 > 断了的数 > 在忙的数，零则不显示）
- 图标绘制：
  - `idle` / `waiting`：模板图（跟随菜单栏深浅色），`waiting` 右上加小圆点
  - `working`：模板图，环上一个更亮的光点沿路径流动（约 12 帧/秒，周期 1.6 秒）
  - `needsYou`：非模板、品牌强调色，轻跳（缩放 1.0↔1.08，周期 1.2 秒）
  - `interrupted`：非模板、琥珀色，静止
- 动画调度：只在需要时跑定时器；系统「减少动态效果」打开时只换颜色与静态形态不播帧；屏幕休眠、锁屏时暂停，唤醒后恢复
- 显示方式（A18）：设置 › 通用新增「菜单栏」分组：仅图标 / 图标 + 数字（存 UserDefaults，默认仅图标）
- 面板里的会话行：`attention` 非空的会话状态图块显示「需要你确认」（图标 `hand.raised`，强调色），排序不变

**Out**
- 通知（T2.3）；宠物（P3）

## Notes / 开放问题 / 澄清日志

- 2026-10-16 实施：`IconAnimator` 放在 MossKit（`Sources/MossKit/IconAnimator.swift`）而不是 CCMoss，因为测试目标只依赖 MossKit；它只决定「哪一帧、要不要跑定时器」，时钟与定时器（`TickScheduler`）可注入。App 侧的绘制、真实定时器与系统状态监听在 `Sources/CCMoss/MenuBarIcon.swift`
- 帧数（最终版见本节末条）：先后试过 12.5、10 帧/秒的流动光点，均因菜单栏每次更新的固定系统开销超预算，已改为每秒至多 2 次更新
- 定时器：只在「在忙 / 需要你确认」且未开减少动态效果、屏幕未休眠未锁屏时运行；其他情况彻底停掉（`Timer.invalidate`），不是空转。锁屏也按休眠处理（`com.apple.screenIsLocked`）。定时器加在 `.common` 模式，菜单打开时也走；容差 25%
- 颜色：需要你确认用品牌色 #FF5A3C；断了用比面板更深的琥珀 #ED9E1A，在浅色菜单栏上也看得清。风险节提到的深色描边没有加：离屏渲染在 1x/2x 的浅、深两种仿菜单栏底色上不加描边已经清楚；真机若在某些壁纸下对比度不够再加
- 在等你的小圆点放在右上角，离环的笔画约 3pt，不与 Continuum 自带的缺口相碰
- 数字（图标 + 数字）直接画进同一张图（等宽数字 12pt semibold），颜色与图标一致；模板态的数字随菜单栏着色
- 预览：`CCMoss --render out.png --icon working|waiting|needsYou|interrupted|idle|all [--frame n | --sheet] [--count n] [--dark] [--scale 1|2]`，在仿菜单栏底色上画出帧（`--sheet` 一行排出全部帧）
- 真机两项（四态录屏、静止时 CPU < 1%）及 `reports/T2.2-manual.md` 由主控在真机完成
- 2026-10-16 真机复测：「在忙」动画时 App 平均 11% CPU。主控 `sample` 显示开销在 SwiftUI 每帧的场景更新（`MenuBarExtra` label 变化触发 `scenesDidChange`、`flushTransactions`、CA 提交）和 `NSStatusItem` 的多显示器副本更新，绘制本身不贵（主控加的位图帧缓存保留）。改为自管 `NSStatusItem`（`StatusItem.swift`）：每帧只设 `button.image`，不经过 SwiftUI；面板改为自管的无边框 `NSPanel`（`PanelController.show()/toggle()`，供 T2.4 全局快捷键、T2.3 通知点击调用）；`MenuBarExtra` 保留为不插入的第一个场景，只为维持「启动不开窗口」。预算由主控修订为：静止 < 1%，动画中 < 3%
- 离屏测量：`CCMoss --bench-icon working|needsYou|idle [--seconds n]`（真实定时器与图标模型，帧设到离屏按钮上，统计本进程 CPU；不含菜单栏与 WindowServer 的工作）
- 2026-10-16 第二次真机复测：自管状态栏后动画中仍约 4.3%（10 帧/秒）、4.2%（6.7 帧/秒）；`sample` 显示每次换图都有固定的系统开销（`_updateReplicants`、CA 提交、`NSViewBackingLayer display`），与帧率几乎无关。改为 Core Animation：两个动画态由叠在状态栏按钮上的 `IconMotionView`（`CAShapeLayer`）播放，在忙 = 两圈路径上 4 段渐隐的 `strokeStart/strokeEnd` 线性动画（每圈加 0.5，首尾无缝），需要你确认 = `transform.scale` 1.0↔1.08 往返；App 每帧不做任何事，不再有定时器。静止态仍是普通图片（模板图）；动画中按钮图片只画数字，环由图层画。图层不是模板图，颜色取按钮 `effectiveAppearance` 下的 `labelColor`，外观变化时重新着色。`IconAnimator` 只决定何时开始/停止连续动画（`MotionDriver`），帧序号只用于离屏审阅图（`IconMotion.sampleCount`，每秒 10 张）。`--render --icon … --layers` 用真实图层摆出各时刻，与静态绘制逐帧一致
- 2026-10-16 第三次真机复测：Core Animation 版更糟（App 26.5%，WindowServer 43.0% 对比退出 App 时 29.6%），推测 macOS 26 每个动画帧都为各显示器的副本重新快照状态栏条目。主控决定（AMEND 由主控记录）：回到换 `button.image`（保留位图缓存），删除图层视图；菜单栏每秒至多 2 次更新（帧间隔 0.5 秒）。在忙 = 环 62% 不透明度，一段比环略粗略长的满不透明度短划每 0.5 秒跳一格，12 格一圈（6 秒），读作慢慢走的进度点；需要你确认 = 品牌色两拍「心跳」（1.0 / 1.07，各 0.5 秒）。预算：静止 0%，动画中 App CPU ≤ 1%，WindowServer 无超出噪声的增加。流畅动画留给 P3 桌面宠物（普通窗口，不被复制）
- 同日用户反馈「icon 太细了」：所有状态笔画由 2.1 加粗到 2.7（18pt），与相邻菜单栏图标（Wi-Fi、锁等系统符号）同量级；图左右各留 0.75pt，容纳加粗后的笔画和 1.07 的心跳。`--render --icon … --compare` 在左侧画几个系统符号对比粗细
- 离屏复测（Release，20 秒）：在忙 0.14%、需要你确认 0.14%（各 40 帧，2.0 帧/秒），静止 0.00%（0 帧）
