## 目标

菜单栏的 Continuum 图标用动画表达会话动态：有会话在忙时环上一个光点缓缓流动；需要你确认时轻轻跳动并带强调色；
有会话断了显示琥珀色；只是在等你时静止加一个小圆点。图标旁可选显示紧凑数字。动画克制、省电。

## Scope（YAGNI）

**In**
- MossKit：`Snapshot` 解码 `attention`（T2.1 已输出）；`IconState` 由会话算出：`needsYou`（任一 running 会话 attention 非空）> `interrupted` > `working` > `waiting` > `idle`；`IconBadge` 给出紧凑数字（需要你的数 > 断了的数 > 在忙的数，零则不显示）
- 图标绘制：
  - `idle` / `waiting`：模板图（跟随菜单栏深浅色），`waiting` 右上加小圆点
  - `working`：模板图，环上一个更亮的光点沿路径流动（约 12 帧/秒，周期 1.6 秒）
  - `needsYou`：非模板、品牌强调色，轻跳（缩放 1.0↔1.08，周期 1.2 秒）
  - `interrupted`：非模板、琥珀色，静止
- 动画调度：只在需要时跑定时器；系统「减少动态效果」打开时只换颜色与静态形态不播帧；屏幕休眠、锁屏时暂停，唤醒后恢复
- 显示方式（A18）：设置 › 通用新增「菜单栏」分组：仅图标 / 图标 + 数字（存 UserDefaults，默认仅图标）
- 面板里的会话行：`attention` 非空的会话状态图块显示「需要你确认」（图标 `hand.raised`，强调色），排序不变

**Out**
- 通知（T2.3）；宠物（P3）

## Notes / 开放问题 / 澄清日志

- 2026-10-16 实施：`IconAnimator` 放在 MossKit（`Sources/MossKit/IconAnimator.swift`）而不是 CCMoss，因为测试目标只依赖 MossKit；它只决定「哪一帧、要不要跑定时器」，时钟与定时器（`TickScheduler`）可注入。App 侧的绘制、真实定时器与系统状态监听在 `Sources/CCMoss/MenuBarIcon.swift`
- 帧数：帧间隔 0.08 秒（12.5 帧/秒）；在忙 20 帧 = 1.6 秒，需要你确认 15 帧 = 1.2 秒。在忙 = 环降到 40% 不透明度、一段带渐隐尾巴的满不透明度光点沿环流动（模板图只能用透明度表达「更亮」）
- 定时器：只在「在忙 / 需要你确认」且未开减少动态效果、屏幕未休眠未锁屏时运行；其他情况彻底停掉（`Timer.invalidate`），不是空转。锁屏也按休眠处理（`com.apple.screenIsLocked`）。定时器加在 `.common` 模式，菜单打开时也走；容差 25%
- 颜色：需要你确认用品牌色 #FF5A3C；断了用比面板更深的琥珀 #ED9E1A，在浅色菜单栏上也看得清。风险节提到的深色描边没有加：离屏渲染在 1x/2x 的浅、深两种仿菜单栏底色上不加描边已经清楚；真机若在某些壁纸下对比度不够再加
- 在等你的小圆点放在右上角，离环的笔画约 3pt，不与 Continuum 自带的缺口相碰
- 数字（图标 + 数字）直接画进同一张图（等宽数字 12pt semibold），颜色与图标一致；模板态的数字随菜单栏着色
- 预览：`CCMoss --render out.png --icon working|waiting|needsYou|interrupted|idle|all [--frame n | --sheet] [--count n] [--dark] [--scale 1|2]`，在仿菜单栏底色上画出帧（`--sheet` 一行排出全部帧）
- 真机两项（四态录屏、静止时 CPU < 1%）及 `reports/T2.2-manual.md` 由主控在真机完成
