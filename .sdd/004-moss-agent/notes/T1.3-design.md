# T1.3 设计笔记：代答中枢（CLI）

依据：spec `T1.3-ask-broker.spec.md`（契约照写）、`notes/ask-probe.md`（2.1.302 实测）、DESIGN A3–A6、C2。

## 模块

| 位置 | 职责 |
|------|------|
| `moss-core::ask` | 纯协议：路径、待答题 / 答案 / 撤回的读写、先答者胜、接手方心跳、过期清理、按会话撤回、把答案拼成 hook 输出。只用 `std` 文件 API，不碰 registry、不碰 tmux |
| `moss-core::agent::HookKind` | 加 `PreToolUse`、`PermissionRequest`（排在 `ALL` 末尾，老安装的 `missing_hooks` 只是多出两项） |
| `moss-core::settings_json` | 按事件给 matcher（PreToolUse → `AskUserQuestion`，PermissionRequest / PostToolUse → `*`）与超时（PermissionRequest 600，其余 10） |
| `moss-core::config` | `[ask] enabled`（缺省 true）、`[ask] wait_secs`（缺省 300，夹到 1..=590）；`ask.enabled` 可经 `config set` 改（写成 TOML 布尔） |
| `cc-moss::cmd::ask_hook` | 两个新 hook 分支 + 观察型 hook 里的「撤回」调用 |
| `cc-moss::cmd::ask` | `ask list [--json]`、`ask answer`、`ask take` |

## 文件协议与原子性（`<state>/asks/`，目录 0700，经 `store_dir::ensure_private_dir`）

- `<id>.json` 待答题：先写同目录临时文件再 `rename`，读者永远看不到半截文件。`id` = 毫秒时间戳 + pid 的十六进制，文件名安全、按时间可排序。
- `<id>.answer.json` 答案：`OpenOptions::create_new(true)`（`O_EXCL`）创建，`EEXIST` → 「已经有人答了」。先答者胜由内核保证，不靠先查后写。写完 `sync_all`。读者解析失败（另一方刚创建、还没写完）当作「还没答」，下一轮再读。
- `<id>.closed.json` 撤回：同样 `O_EXCL`，第一个理由算数，后来的撤回静默忽略。
- `takers/<名字>.alive`：`ask take` 创建或刷新 mtime。名字只许 `[a-z0-9_-]`。
- 过期清理：`expires_at + 1 小时` 之前的整组文件（待答题、答案、撤回）在 PermissionRequest 建题时与 `ask list` 时顺手删。撤回的题留一小时，让 App 能显示「已在会话里回答」。

`ask list` 只列「没撤回、没答案、没过期」的题。

## 两个新 hook

**PreToolUse（matcher `AskUserQuestion`）——只记录，绝不等待。** 开关开、有接手方时写一份 `kind: question` 的待答题（带 `tool_use_id`）；否则什么都不写。全程不轮询、不睡眠。

**PermissionRequest（matcher `*`）——唯一会等的地方。**

1. 读配置：读不到 / 解析失败 / `enabled = false` → 立即返回。
2. 接手方：`takers/*.alive` 里没有 90 秒内的 → 立即返回（不建题）。
3. 建题：`AskUserQuestion` → 先找同会话、同 `prompt_id`、同 `questions`、10 秒内由 PreToolUse 建的、还开着的题，找到就沿用（补上 `tool_use_id` 那份），否则新建；其他工具 → `kind: permission`，`tool.preview` 取 `command` / `file_path` / `url` / 整个 `tool_input` 的紧凑 JSON，截到 300 字。`session_name` 从 registry 尽力取，取不到就省略。
4. 等待循环：每 150 ms 看一次（≤ 200 ms）：
   - 有答案且能解析、且与题型相符 → 先写 `closed {"reason":"answered"}`，再打印回填 JSON，退出；
   - 有撤回 → 无输出退出；
   - 到 `wait_secs` → 写 `closed {"reason":"timeout"}`，无输出退出。
   - hook 的 `timeout` 600 > `wait_secs` 上限 590，Claude Code 杀进程之前一定是 hook 自己先退。
5. 答案形状不对（选择题给了 allow，或答案里缺题）→ 当作没答，继续等到超时，不输出可能被会话误用的东西。

回填（A6）：`{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow","updatedInput":{"questions":<原样>,"answers":{…}}}}}`；权限题 `{"behavior":"allow"}` 或 `{"behavior":"deny","message":…}`。

## 撤回触发

观察型 hook 读完 stdin、过了「是否交互会话」判断之后，调用一次 `ask_hook::withdraw(kind, payload)`：

| 事件 | 撤回哪些 | 理由 |
|------|---------|------|
| PostToolUse | 同会话、工具名相同的开着的题（AskUserQuestion 的题被答了，或 `--safe` 会话里终端先批了这个工具） | `answered-in-session` |
| UserPromptSubmit、Stop | 同会话所有开着的题（对话框已经不在了：答了、或按 Esc 走开了） | `answered-in-session` |
| SessionEnd | 同会话所有开着的题 | `session-ended` |

PostToolUse 的工具名匹配比 spec 的「PostToolUse(AskUserQuestion)」宽一点：权限题在终端被批后也会撤回，否则 App 会挂着一道已经没用的题；误撤回的最坏结果是 hook 提早不表态，回落到今天的行为。

等待中的 hook 每 150 ms 看一次撤回文件，所以撤回后 1 秒内必退出。

终端里按 Esc 取消（2.1.302 实测，见 `ask-probe.md` 补测）：没有 PostToolUse，Claude Code 直接结束等待中的 hook 进程，题目留着；
这一轮随即结束触发 Stop，由 Stop 撤回；兜底是 `expires_at` 过后不再列出。

## 与现有 6 个观察型 hook 的隔离

- `hook::run` 里先按事件分流：`pre-tool-use` / `permission-request` 走 `ask_hook`，其余六个照旧走原来的 `handle`，原路径的代码不挪。
- 观察型 hook 新增的只有 `withdraw` 一步，而它第一件事是 `read_dir(<state>/asks)`：目录不存在或没有开着的题（绝大多数时候）就直接返回，不解析 payload、不读配置。只有确有开着的题时才做第二次轻量解析（只取 `session_id`、`tool_name`）。
- `withdraw` 的错误只进 `hook.log`，不影响后面的 registry 写入。
- 延迟对比：`tests/hook_latency.rs` 交替跑基线二进制（改动前 010bc76 的 release 构建）与本次构建，每个事件 200 次，比 p95。

## fail-open 的位置（一律无输出、exit 0）

| 位置 | 情形 |
|------|------|
| `hook::run` 的 `catch_unwind` | 两个新分支同样包在里面：panic、任何 `Err` 只记 `hook.log` |
| 配置 | 读不到、TOML 坏了、`enabled = false` |
| 接手方 | 没有、`takers` 目录读不了 |
| 状态目录 | 建不了、写不了待答题（只读、被文件占位、权限错） → 直接返回，不等待 |
| payload | JSON 坏、缺 `session_id`、`tool_input` 没有 `questions` → 不建题 |
| 非交互会话 | `claude -p` / SDK：与现有 hook 一样跳过 |
| 等待中 | 读答案出错、答案形状不对 → 继续等；到点 → 超时退出 |

输出只在一个地方发生：等到合法答案后的那一次 `println!`。

## 不做

- kqueue / inotify 盯文件：150 ms 轮询在 300 秒内是 2000 次 `stat`，足够便宜，且两个平台一样。
- 等待中途接手方掉线就提早退出：spec 只要求「开始时有接手方才等」；终端对话框始终可答，晚退出无害。
- CLI 一次多题里的自由文字：`--text` 只用于单题；多题的自由文字由 App / 守护进程直接写答案文件。
