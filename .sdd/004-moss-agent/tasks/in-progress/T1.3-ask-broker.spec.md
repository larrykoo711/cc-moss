## 目标

会话问选择题（AskUserQuestion），或 `--safe` 会话要权限时，cc-moss 把完整的问题记下来，任何一方（以后的桌面、Slack、Moss，现在先是 `cc-moss ask answer`）答了，答案就交回会话，会话照常继续；用户也可以照旧在终端里答，谁先答算谁的。没人接手、出错、超时时，会话和今天一模一样。

## Scope（YAGNI）

**In**：
- 新 hook（受管写入 `~/.claude/settings.json`，与现有 6 个并列）：
  - `PreToolUse` matcher `AskUserQuestion` → `cc-moss hook pre-tool-use`：只记下题目（带 `tool_use_id`），立刻退出
  - `PermissionRequest` matcher `*` → `cc-moss hook permission-request`：建待答题、等答案、按 A6 回填；`timeout` 600
- ask 文件协议（`<state>/asks/`）：待答题、答案（`O_EXCL` 先答者胜）、撤回；过期清理
- 「有接手方才等」：接手方心跳 `<state>/asks/takers/<名字>.alive`（mtime 90 秒内算在）；`cc-moss ask take --name <名字>` 刷一次心跳（App 与守护进程后续定期调用；测试与 CLI 也能用）
- 撤回：同会话 `PostToolUse(AskUserQuestion)`（题目被答了，不管谁答的）、`UserPromptSubmit`、`Stop`、`SessionEnd` → 关闭该会话所有待答题
- 命令：`cc-moss ask list [--json]`、`cc-moss ask answer <id> (--choice <label>… | --text <文字> | --allow | --deny [--message <文字>])`、`cc-moss ask take --name <n>`
- 配置：`[ask] enabled = true`（缺省开；没有接手方时等于没开）、`[ask] wait_secs = 300`（上限 590，留 10 秒给 hook 收尾）
- 假 claude 能发 PreToolUse / PermissionRequest 并把 hook 的输出存下来；e2e
- 文档：guide 中英加「替会话接住问题」一节（CLI 部分）；CHANGELOG

**Out**：
- 桌面界面（T1.4）、Slack（T4.x）、路由与在场（T4.2）
- Elicitation（MCP）：cc-moss 不提供 MCP server
- 「等你输入」（idle）：不是阻塞提示，T1.4 用现有 `send` 回复

## 契约（protocol literal：CLI、App、守护进程、Slack 共用）

- 目录（2026-10-18 评审修正后的终态）：
  - `<state>/asks/<id>.json`：还立着的题（开着，或已有答案但等着的 hook 还没取走）；整份写临时文件再 `rename`
  - `<state>/asks/done/<id>.json`：关闭后挪到这里（先 `link` 再删原处，不覆盖已有的）；观察型 hook 只看 `asks/` 顶层，关掉的题不拖慢它们
  - `<state>/asks/<id>.answer.json`：答案。写临时文件、`sync` 后 `hard_link` 到这个名字：`EEXIST` = 已经有人答了（与 `O_EXCL` 同义），读者永远看不到半截文件。**其他客户端（App、Slack）必须照此写**，不得原地写
  - `<state>/asks/<id>.closed.json`：关闭理由，同样 link 落地、先到者算数：`{"reason": "answered"|"answered-in-session"|"timeout"|"session-ended"|"invalid-answer"}`；`invalid-answer` = 答案能解析但对不上题（缺题、选择题给了 allow、权限题给了 answers），或 2 秒后仍解析不了，hook 立即放手
  - 答案与关闭文件留在 `asks/` 顶层，直到题目从 `done/` 里被清掉（过期一小时后）；没有题目的孤儿文件按文件名、过一小时清掉
  - `takers/<名字>.alive`
  - 写答案的一方想知道结果：写完后看 `<id>.closed.json` 的理由（`answered` = 会话收下了）
  - 只用属于当前用户、权限 `0700` 的 `asks/`；打开文件一律 `O_NOFOLLOW`
- 待答题 `schema: 1`：`id`、`kind`（`question` | `permission`）、`session_id`、`prompt_id`、`tool_use_id?`、`session_name?`（PreToolUse 记下时没有，PermissionRequest 接手时补上）、`cwd`、`created_at`、`expires_at`、
  `questions[]`（`question`、`header`、`options[{label,description}]`、`multiSelect`；原样取自 `tool_input`）或 `tool`（`name`、`preview` ≤ 300 字且遮住常见密钥格式、`input_hash?`：cc-moss 内部用，`tool_input` 按键排序后的 FNV-1a 64 位十六进制，PostToolUse 只撤回同一次调用）
- 答案 `schema: 1`：`by`（`cli` | `desktop` | `slack` | `moss`）、`answers?`（`{问题原文: label 或 "a, b" 或自由文字}`）、`behavior?`（`allow` | `deny`）、`message?`；选择题只给 `answers` 且每题都有，权限题只给 `behavior`
- hook 输出（回填）：`{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow","updatedInput":{"questions":<原样>,"answers":{…}}}}}`；权限题 `allow` / `deny`（+`message`）
- 命令：`ask list --json` 输出 `{"schema":1,"asks":[…待答题…]}`

## 风险与回退

- hot-path：hook 在每次权限询问 / 选择题时同步运行。一切异常 fail-open（无输出、exit 0）；PreToolUse 观察分支不等待
- 安全：答案文件写在 `0700` 的状态目录里；`ask answer` 只接受存在且未关闭的题；权限题的 `allow` 只来自用户明确操作
- 回退：`cc-moss config set ask.enabled false`；uninstall 去掉新 hook
