## 目标

面板侧栏加第三页「Moss」：上面一眼看清 Moss 的状态（在不在、在干什么、排着几条），下面像聊天一样和 Moss 说话、看它回复。Moss 也会收到各会话的动态（需要你 / 断了 / 做完了），不用你转述。

## Scope（YAGNI）

**In**：

- **送信（守护进程独占，A9 / A12）**
  - App 与 CLI 都不碰 Moss 的 tmux：`cc-moss moss say [--json] -- <text>` 只在 `<state>/moss/inbox/` 写一条（`O_EXCL`、`<ulid>.json`），立即返回 id
  - 守护进程串行处理 inbox：Moss 正在一轮里时排队；空闲时 `load-buffer` + `paste-buffer -p -d` 粘贴 → 300ms 后 `capture-pane` 回读末尾 12 个字符 → 回车只用 `send-keys Enter`；回读不到重贴一次，再不到发 Esc 后再贴一次，仍失败记 `failed`（正文永远不走 `send-keys -l`）
- **取回复（`reply.rs`，K2 降级）**
  - Moss 的项目设置加 Stop hook：`cc-moss hook moss-stop` 写 `<state>/moss/stop/<ts>` 标记
  - 守护进程见到标记后在 Moss 的 transcript 里：找时间戳晚于注入时刻、含末尾片段的 user 条目 → 之后**时间戳最大**、非 sidechain、`stop_reason` 为 `end_turn` / `stop_sequence` 的 assistant 文本；标记先到 transcript 后到，轮询 3 秒
  - 认领不到（格式变了、`/clear` 换文件找不到）→ 记一条「已收到」（`fallback: true`），不卡队列
  - 一轮超过 300 秒：画面还在运行就不打断，挂迟到认领（15 分钟）；画面是确认框就记「Moss 在等确认」，不按 Esc
- **对话记录**：守护进程追加 `<state>/moss/chat.jsonl`（一行一条：`id`、`at`、`from: you|moss|events`、`text`、`state: queued|sent|replied|failed`、`fallback?`、`reply_to?`、`buttons?`）；只追加，超过 2000 行时轮转一份 `.1`。App 经 FSEvents 监视
- **动态摘要**：守护进程看 registry 的状态变化（需要你 / 断了 / 做完了，Moss 自己除外），20 秒窗口内合并成一条「[动态] …」，Moss 空闲时注入；同一会话同一状态 10 分钟内不重复；`[moss] digest = true` 可关
- **回复控制标记**：Moss 回复里的 `[[silent]]`（不在面板显示、不提醒）与 `[[buttons: 甲 | 乙]]`（面板上渲染成按钮，点了等于发那一句）；标记从显示文本里去掉；`moss-sessions` skill 教 Moss 怎么用
- **状态（`moss status --json` 加字段）**：`activity: idle|thinking|waiting|offline|off`（`thinking` = transcript `turn_open`；`waiting` = 画面上是确认框）、`queued: int`、`last_reply_at?`
- **App「Moss」页**（侧栏第三项，⌘3，在「待处理」下面）
  - 顶部状态条：头像 + 「Moss」+ 状态点与一句话（「待命中 · 已运行 2 小时」「正在想…」「在等你确认，去终端看看」「重启中，30 秒后再试」「已关闭 — 去设置打开」）+ 「在终端打开」按钮（attach Moss 的 tmux）
  - 对话流：你的话靠右、Moss 的靠左（支持 Markdown 基本格式与代码块）、动态摘要是居中的灰色小字一行；排队 / 发送中 / 失败显示在你那条下面，失败可重发
  - 底部默认是一排**内置动作**（点一下就把这件事发给 Moss），末尾一个键盘图标；点键盘才换成输入框（回车发送、⇧回车换行），再点一下换回动作。动作是数据（`MossAction`：图标、中英标题、发出的话），T2.4 / T3.1 往里加；本任务只放 Moss 现在做得到的三件：谁在等我、谁卡住了、今天做了什么。Moss 关闭或守护进程没跑时动作和键盘都禁用并说明原因
  - 侧栏图标上的状态点（在想 = 呼吸点，有未读回复 = 品牌色点）
  - 空状态：头像 +「Moss 能帮你看着这些会话」+ 三个动作的大行（图标、标题、一句说明），不放开放式的输入提示
- **提醒路由（A23 延续）**：你从面板发的话，回复到达时面板开着且在 Moss 页 → 不提醒；否则小莫显示时冒泡（点「打开面板」到 Moss 页），不显示时发系统通知；`[[silent]]` 不提醒
- **头像（Q2）**：∞ 标志的圆角方块变体，品牌色底；`IDENTITY.md` 改名后页面标题跟着变
- **文档**：guide 中英「和 Moss 对话」一节（隐私：只有你发的话和会话动态进 Moss，不读其它会话的对话内容）；CHANGELOG

**Out**：

- 在 Moss 的终端里直接打的字不进对话流（只有经 inbox 的进；在终端里就看终端）
- Slack 渠道：T4.1（inbox 的 `from` 预留 `slack`）；体检：T2.4；派发：T3.1
- 流式显示 Moss 正在写的回复：先只显示「正在想…」，整条回来再显示
- 自动 `/compact` / `/clear` 策略：本任务记录实际对话量，R1 前再定

## 契约

- `cc-moss moss say [--json] -- <text>`：成功输出 `{"schema":1,"id":"<ulid>"}`；Moss 关闭 / 守护进程没跑时退出 1 并说明
- `<state>/moss/inbox/<ulid>.json`：`{"schema":1,"id","at","from":"you","text"}`
- `<state>/moss/chat.jsonl`：见 Scope；未知字段忽略
- `moss status --json` 加字段：`activity`、`queued`、`last_reply_at`（schema 1 不变）
- Moss 的项目设置加 `hooks.Stop`：`'<cc-moss>' hook moss-stop --home '<home>'`

## 实施步骤（TDD 序）

1. 红：inbox 写入与排队顺序；注入的回读判定（找到 / 找不到重贴 / Esc 后重贴 / 失败）——假 tmux
2. 红：认领——按时间戳取最大、跳过 sidechain、标记先于 transcript 的 3 秒轮询、`/clear` 换文件、认领不到降级——用 fixture transcript
3. 红：摘要合并窗口与 10 分钟去重；控制标记解析
4. 绿：实现；`moss say`、`hook moss-stop`、status 字段、模板（Stop hook、`moss-sessions` skill）
5. App：`MossPage`（状态条、对话流、输入框）、侧栏第三项与状态点、提醒路由
6. e2e（独立 tmux socket、临时 HOME 与状态目录、假 claude 回声脚本按协议写 transcript 并触发 Stop）：`moss say` → chat.jsonl 出现 Moss 回复；把一个会话标成断了 → 30 秒内 Moss 收到摘要
7. 真机：controller 用临时 `CC_MOSS_STATE_DIR` 跑真 claude 一次，问一句、拿到回复，按规则 `/exit` 并清理

## 风险与回退

- K2 transcript 格式变化：认领单独封装、降级为「已收到」，不卡队列
- 往 Moss 输入框粘贴时你正 attach 在 Moss 终端里打字：守护进程只在 Moss 空闲且输入框为空（回读最后一行是空提示符）时粘贴，否则等下一拍
- 额度：摘要 20 秒合并、10 分钟去重、可关；Moss 空闲不发请求
- 回退：`[moss] digest = false` 停摘要；关掉 Moss 后 Moss 页只读显示历史
