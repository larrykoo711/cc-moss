## 目标

Moss 是一个一直在的 Claude Code 会话：守护进程登录后把它拉起来；它被杀、崩溃或 tmux 没了，守护进程按阶梯把它重新拉起，它读自己的台账接着干；cc-moss 的列表、命令、面板里都结束不了它，只有设置里关掉 Moss 才真正停。它有自己的家、人设和日志。

## Scope（YAGNI）

**In**：
- Moss 的家 `<state>/moss/`（默认 `~/.local/state/cc-moss/moss/`，不在受隐私保护的目录下）：
  - 受管文件（每次 install 覆盖）：`CLAUDE.md`（`@` 引入 SECURITY / IDENTITY / SOUL / USER；`SESSIONS.md` 不引入，按需当资料读）、`SECURITY.md`、`.claude/settings.json`（防护 hook）、`.claude/skills/moss-profile/SKILL.md`
  - 用户 / Moss 自己的文件（只在不存在时创建，之后绝不覆盖）：`IDENTITY.md`（默认名字 Moss）、`SOUL.md`、`USER.md`、`journal/`、`memory/`
  - 生成文件：`SESSIONS.md`（守护进程按 registry 生成会话一览，每 60 秒或会话变化时刷新）
- 模板随二进制发布（`include_str!`），install 布置、升级时只更新受管文件
- 防护 hook（项目级 PreToolUse，全部工具）：拒绝写 Moss 家以外的文件、拒绝改自己的 `.claude/settings.json` 与 hook、拒绝改 `SECURITY.md`；`IDENTITY` / `SOUL` / `USER` 只能经 `/moss-profile`；不认识的工具（含 MCP）一律拒绝
- Bash 沙箱（Claude Code 的 `sandbox`，项目设置里打开且严格）：命令行只能写家、临时目录和 registry 文件（评审修正轮 I1）
- 守护进程看护 Moss：
  - 专用 tmux socket `cc-moss-moss`，会话名 `moss`，在 Moss 家里启动 `claude --dangerously-skip-permissions --session-id <新 uuid> "<开机提示>"`，环境带 `CC_MOSS_ROLE=moss`
  - 每 60 秒判活（`tmux has-session`），只有明确的「找不到会话 / 没有 server」才算死，其余一律当活着；死了按 T2.1 的 `Watchdog` 阶梯（30s / 2m / 10m / 1h）重启；起不来走 `start_failed`
  - 每次都全新启动（不 resume）；重启时把旧的 Moss 记录关掉（不再提示恢复）
  - 开机提示：「你是 Moss。先读 SESSIONS.md 和今天的 journal，接着上次没做完的事；没有就安静待命。」
- registry 记下角色：hook 看到 `CC_MOSS_ROLE=moss` 时登记 `role: moss`；`ls --json` 加 `role` 字段（加字段，schema 不变）
- 保护：`pick` 不对 Moss 提供结束（提示「Moss 由 cc-moss 照看，要关掉请到设置」）；`close` 拒绝 Moss；App 面板把 Moss 固定在最上面一行，不提供「不再提醒」
- 开关：`[moss] enabled = true`（缺省开）；`cc-moss moss start|stop|status [--json]`；关掉时守护进程结束 Moss 且不再拉起；App 设置「Moss」页加开关与状态（运行中多久、重启过几次）
- 守护进程 plist：`ProcessType` 改 `Standard`（M13：`Background` 会把 Moss 和它起的进程压成低优先级）；`EnvironmentVariables` 加 `PATH`（install 时的 PATH，补上 Homebrew 与 Claude Code 的常见目录），让守护进程找得到 `claude` 与 `tmux`
- doctor：Moss 状态、找不到 `claude` / `tmux` 时的修复提示
- 文档：guide 中英「Moss」一节（是什么、在哪、怎么关、隐私：它用你的 Claude Code 登录、空闲不耗额度）；CHANGELOG

**Out**：
- 和 Moss 对话、注入消息、认领回复、事件摘要：T2.3
- Doctor：T2.4；派发：T3.1（届时处理 K7：在 `~/Documents` 下起会话的隐私授权）
- 自动压缩策略、定期 `/clear`：T2.3 根据实际对话量再定
- Moss 头像：Q2，T2.3 做面板对话视图时一起定

## 契约

（2026-10-18 评审修正轮改到终态，controller 预先批准；见 `notes/T2.2-design.md`）

- 环境变量（守护进程 `new-session -e` → claude → hook）：`CC_MOSS_ROLE=moss` 与 `CC_MOSS_MOSS_SESSION=<启动时的 uuid>`；hook 只在 `CC_MOSS_ROLE=moss` **且** SessionStart 的 `session_id` 等于 `CC_MOSS_MOSS_SESSION` 时登记 `role: moss`
- `ls --json` 会话新增可选字段 `role`（`"moss"`），schema 1 不变（加字段）
- tmux：socket `cc-moss-moss`（`tmux -L cc-moss-moss -f /dev/null`，不读用户的 tmux.conf），启动时会话名 `moss`；认 Moss 靠会话的用户选项 `@cc-moss-role=moss`（改名后仍是 Moss）；判活 `list-panes -a -F '#{session_id}|#{@cc-moss-role}|#{pane_dead}'`，有标记且 pane 未死 = 活，pane 全死（`remain-on-exit`）= 死并清掉；会话上设 `destroy-unattached off`、窗口 `remain-on-exit off`
- registry 关闭旧 Moss：`close_role(role, socket, keep)` 只关 tmux socket 文件名等于 Moss socket 的记录、不关刚起来的那条；`end_reason` 取 `moss-restarted` / `moss-stopped` / `daemon-stopped` / `uninstalled`
- Moss 的项目设置 `.claude/settings.json`：
  - `hooks.PreToolUse`：matcher `*`，命令 `'<cc-moss>' hook moss-guard --home '<home>' || exit 2`；防护只认命令行里的 `--home`（不读 `CLAUDE_PROJECT_DIR`），没有就拒绝
  - `sandbox`：`enabled: true`、`failIfUnavailable: true`、`allowUnsandboxedCommands: false`、`autoAllowBashIfSandboxed: true`、`excludedCommands: ["cc-moss moss profile *"]`、`filesystem.allowWrite`：`<state>/registry.db` 及其 `-wal` `-shm` `-journal`、`filesystem.denyWrite`：`./SECURITY.md` `./CLAUDE.md` `./SESSIONS.md` `./IDENTITY.md` `./SOUL.md` `./USER.md`
- `cc-moss moss profile <identity|soul|user> [--from <file>]`（隐藏命令，`/moss-profile` 用 `--from` 形式，它是唯一在沙箱外跑的命令）
- `moss status --json`：`{"schema":1,"enabled":bool,"running":bool,"since":rfc3339?,"restarts":int,"session_id":str?,"daemon_running":bool,"last_error":str?}`（后两项为本轮加字段；`last_error` 只在开着且没在运行时出现，来自 `<state>/daemon/moss-error.txt`）
- 守护进程 plist `EnvironmentVariables` 加 `CC_MOSS_CONFIG`（install 时的配置文件绝对路径）；`moss start|stop|status` 读写它指的那个文件
- `cc-moss daemon stop` 同时结束 Moss（不动开关）；升级的 `kickstart -k` 不停 Moss，新守护进程接管

## 风险与回退

- 额度：Moss 一直开着但空闲不发请求；开机提示让它没事就待命。T2.3 再控制摘要频率
- 「杀不掉」与用户意愿：设置里关掉 / `moss stop` / `[moss] enabled = false` 都能真正停下
- 安全：Moss 是 bypass 会话；防护 hook 只允许它写自己的家；它的手（派发、关闭等）到 T3.1 才有，且都经 cc-moss 命令与审计
- 回退：`cc-moss moss stop` 或关掉开关；uninstall 移除受管文件但保留用户文件（journal / memory / 人设）
