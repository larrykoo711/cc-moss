## Goal

Moss 每次启动都不会停在 Claude Code 的 bypass 警告框上。跳过警告的键写在 Claude Code 对这个键认的本地级设置（`.claude/settings.local.json`），一律写，不看用户级设置。

## Scope

- `crates/moss-core/src/provider.rs` `moss_settings`：输出里加 `skipDangerousModePermissionPrompt: true`（有没有供应商设置都写，所以没有供应商时 `settings.local.json` 也要生成）。
- `crates/cc-moss/src/cmd/moss.rs`：`sync_provider` 跟着写；项目级 `settings_json` 不再加这个键（项目级无效，留着会误导）；改正 `moss.rs:245`、`moss.rs:1601-1605` 两处与实现不符的注释。
- `crates/moss-core/src/moss/home.rs`：`prune` 保留 `settings.local.json`（现有行为，要有测试守住）。
- 不改普通新会话（它们靠用户级设置，`setup.rs:91-104`，已有测试）。

## Success criteria

- [x] logic：无供应商、有第三方供应商、有 `apiKeyHelper` 三种情况下，`moss_settings` 输出都含 `skipDangerousModePermissionPrompt: true`，原有 `env` / `apiKeyHelper` 字段不变。
      verify: `cargo test -p moss-core moss_settings_skips_bypass_prompt`
- [x] logic：临时 HOME 下 `lay_out` 再 `sync_provider` 之后，Moss 家 `.claude/settings.local.json` 有这个键且为 `true`；项目级 `.claude/settings.json` 不再有这个键；再跑一遍 `lay_out`，`settings.local.json` 仍在。
      verify: `cargo test -p cc-moss moss_home_bypass_key_in_local_settings`
- [x] e2e（探针）：独立 tmux socket + 临时 HOME，按 Moss 的参数（`--dangerously-skip-permissions --setting-sources project,local`）起真 Claude Code，窗格 20 秒内不出现「Bypass Permissions mode」；把键只放项目级时出现（对照组）。结论与 Claude Code 版本记 `reports/moss-bypass-probe.md`。
      verify: `cargo test -p cc-moss --test moss_bypass_probe -- --ignored --nocapture`

探针只证明当前 Claude Code 版本的行为；版本号写进报告。探针跑不起来（例如临时 HOME 下 Claude Code 先要求登录或选主题，到不了警告框）时如实记录，并以 `notes/claude-code-facts.md:10` 的既有事实作证据，不宣称已验证。
