# T2.30-working-ring-cpu — 面板关着时「工作中」小环不再耗 CPU

- Source: 用户 2026-11-22「查一下 cc-moss 为什么空闲也占 30%」→ 选「按 1 + 2 修」
- Evidence: 本机 0.3.13 实测（2026-11-22）：菜单栏 App 38–49% CPU、2.5 天累计 228 分钟；`sample` 5 秒主线程约 70% 忙于 `NSHostingView.layout` → `PanelView` / `SessionRow.body` / `L.ago`；面板窗口 `onscreen=false`（`orderOut` 隐藏，`StatusItem.swift:150`）；当时 3 个会话工作中；`ls --json` 30 秒仅约 2 次，不是主因。根因 `WorkingRing`（`Components.swift:412`）用 `TimelineView(.animation(minimumInterval: 1/30))`，只在「减少动态效果」时暂停，每帧触发整窗排版。
- arch_level: no
- depends_on: []
- verify_layers: [unit, ui]
- risk: hot-path
- mutations:
  - point: 面板隐藏时小环仍在转  red: `testRingStopsWhenPanelHidden`
  - point: 减少动态效果时小环仍在转  red: `testRingStopsWithReduceMotion`

## 目标

有会话在工作、面板关着时，菜单栏 App 不再因为「工作中」小环持续占用 CPU；面板打开时小环照样转，但不再每帧重排整个面板。

## Scope（YAGNI）

**In**
- 纯函数 `WorkingSpin.runs(panelShown:reduceMotion:)`（MossKit）：只有面板显示且未开「减少动态效果」时才转
- `WorkingRing` 改为 Core Animation 图层自转（`CAShapeLayer` + 无限旋转动画，渲染交给系统渲染进程），不再用 `TimelineView` 逐帧驱动 SwiftUI；不转时移除动画，显示静止的弧
- 面板根视图把 `model.panelShown` 经环境值传给小环；其他宿主默认视为可见
- 外观不变：11 pt、品牌色、线宽 1.8、圆头、弧长 72%、1.1 秒一圈、顺时针，居中不漂移

**Out**
- `ls --json` 单次 1.8 秒、141 KB 的优化（另议）
- 守护进程每秒一次 `ps` 存活检查（3–9%，另议）
- 桌宠 `PetLayer` 的动画（已是 Core Animation）

## Success criteria

- [x] `WorkingSpin.runs` 四种组合正确（显示+正常=转；隐藏、减少动态效果、两者皆有=不转）
  verify: `cd apps/macos && swift test --filter WorkingSpinTests`
- [x] App 全量单测通过
  verify: `cd apps/macos && swift test`
- [x] 离屏渲染含工作中会话的面板，小环在图标中央、外观与改前一致
  verify: `cd apps/macos && swift run CCMoss --render <out.png> --demo` 改前改后对比图
- [x] 真机：有会话工作、面板关着时，App CPU 从 38–49% 降到 ≤ 5%（`ps -o pcpu` 连续 30 秒取样均值）
  verify: 本机换装后 `ps -o pcpu= -p <App pid>` 采样
- [x] 真机：面板打开时小环在转，App CPU 明显低于改前
  verify: 面板打开时同法采样（用户打开面板，我不做鼠标模拟）

## 验收记录（2026-11-22）

- 单测：`WorkingSpinTests` 3 条先红后绿；App 全量 1005 条通过（`scripts/swift.sh test`）。
- 离屏渲染（演示数据，亮 / 暗）：改前改后差异只在两个小环区域；尺寸、线宽、颜色、居中一致，仅静止角度不同（旧环的静止角度随渲染时刻而变）。
- 真机（3 个会话工作中）：面板关着 30 秒平均 42%（14.2 秒 CPU）→ 0.1%（0.13 秒）；面板打开（窗口确认在屏幕上）30 秒平均 0.6%（0.23 秒），用户确认面板已打开。新 App 运行 6 小时 28 分钟累计 CPU 103 秒（平均约 0.44%），90 秒逐秒采样只有每分钟一次刷新带来的两次短尖峰（8%、13%）。
