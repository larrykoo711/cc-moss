## 目标

用 cc-switch（或手改 settings）换了供应商之后，你不用退出会话、不用重进 tmux、不用再敲名字：

- 能直接生效的切换（第三方之间：地址、token、模型别名），cc-moss 告诉你「已切到 <地址>，下一条消息就走它」，什么都不用做。
- 运行中的进程吃不进去的切换（切回官方订阅、改了固定模型），cc-moss 把受影响的会话标成「要重开」，在列表里一键（或一次全部）原地重开：同一个 tmux 窗格、同一段对话，接着聊。

## Scope（YAGNI）

**In**
- **供应商快照**：读 Claude Code 用户级 settings（`$CLAUDE_CONFIG_DIR` 或 `~/.claude/settings.json`）里决定供应商的字段：`env` 中 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_API_KEY`、`ANTHROPIC_MODEL`、`ANTHROPIC_DEFAULT_*_MODEL`，顶层 `model`、`apiKeyHelper`。快照只记**键名、base URL 的主机名、模型名**；token / key 的值一律不读出、不落盘（只比较「有没有」）
- **会话的生效快照**：SessionStart 时记下当时的快照；之后守护进程看到 settings 变化，把出现过的键名并进该会话（进程里删不掉的键会一直留着）
- **判定**（纯函数 `provider::verdict(started, seen_keys, now) -> Live | NeedsRestart(reason)`）：
  - 当前缺了会话见过的任一键 → 要重开（典型：切回官方订阅）
  - `ANTHROPIC_MODEL` 或顶层 `model` 与会话启动时不同 → 要重开
  - 其余（值变了、新增键）→ 下一条消息生效
- **监听**：守护进程监听 settings 文件（沿用其现有轮询节奏即可，≤2 s），变化时写一条事件 `provider-changed {host, restart_needed: [slot…]}`，App 和 `ls --json` 据此显示
- **`cc-moss restart <会话>…`**：在原 pane 里重开：
  - 会话空闲：先给 pane 设 `remain-on-exit on`，SIGTERM 让 Claude Code 自己退出（同 `adopt`，等最多 10 s），再 `respawn-pane` 跑 `claude --resume <id> --name=<名字> <白名单启动参数>`，最后恢复 `remain-on-exit`；pane 由 shell 托着 claude 的老布局（claude 是 shell 的子进程）则在 shell 里送入同一条命令
  - 会话忙：默认排队，守护进程在它的 Stop 之后再重开；`--now` 立即重开（CLI 先问一句「这一轮会丢，重开后可以发 continue」，`--yes` 跳过）
  - 当前 settings 指定了 `ANTHROPIC_MODEL` 或 `model` 时，重放的启动参数去掉 `--model`
  - 不在 tmux 里的会话：不重开，提示用 `adopt`（它本来就是「退出再在 tmux 里接着来」）
  - Moss 也受影响：交给 keeper 重开它，不走这条路
- **`cc-moss restart --stale`**：重开所有「要重开」的会话（忙的排队）
- **App**：
  - 切换后面板顶部一条提示：可直接生效时「已切到 <主机名>，下一条消息就走它」；有要重开的会话时「N 个会话要重开才能用上新供应商」+ 按钮「全部重开」
  - 要重开的会话行上有标记和「重开」行内操作；忙的显示「这轮结束后重开」
- `ls --json` 每条多 `provider_restart`（null 或原因代码）；`doctor` 多一行供应商（主机名 + 是否有会话待重开）

**Out**
- 自带供应商切换界面 / 存供应商列表：cc-switch 已经做了，不重复
- 自带本地转发代理（Routing 那种）：能让「切回官方」也免重开，但要转发 OAuth，未验证，留作后续
- 项目级 `.claude/settings*.json` 里的 `ANTHROPIC_*`：只在 doctor 里提示「这个目录自己指定了供应商，切换对它不生效」，不参与判定
- 没人确认就自动重开：重开会打断你，必须点或敲命令

## 行为口径

| 项 | 口径 | 来源 |
|----|------|------|
| 能热生效的切换 | 只提示，不重开 | 实测（notes） |
| 要重开的判定 | 删键或换固定模型 | 实测（notes） |
| 忙的会话 | 默认等这轮结束；立即重开要你确认会丢一轮 | controller 默认 2026-10-20 |
| 重开位置 | 原 pane，tmux 会话名、窗口不变 | 用户诉求 |
| 秘密 | token / key 的值永不读出、不记录，只记「有没有」 | constitution |

## 契约

- 事件 `provider-changed`（`events --json` 可见）：`{host, restart_needed: [slot_id]}`
- registry 新列 `provider_started TEXT NULL`（JSON：键名集、主机名、模型）、`provider_seen_keys TEXT NULL`（迁移只加可空列）
- 新命令 `restart <NAMES>… [--now] [--yes] [--stale] [--json]`
- `ls --json` 新字段 `provider_restart`

## 风险与回退

- 重开会结束进程：只在你点或敲命令后发生；忙的会话默认等，不丢工作
- `remain-on-exit` 只在重开期间对这一个 pane 打开，结束（含失败）后恢复，失败时 pane 留着并提示手动 `--resume`
- 只依赖 2.1.303 实测的热重载行为；Claude Code 改了行为时最坏是多提示一次「要重开」，不会误判成功（提示里建议用 `/status` 确认）

## AMEND-2（2026-10-20，精确化，见 PLAN）

- 重开判据：删键，或 env `ANTHROPIC_MODEL` 变了 → 要重开。顶层 `model`（`/model`）永不要求重开；`--model` 只在 env 设了 `ANTHROPIC_MODEL` 时从重开参数里去掉。
- 每个会话对照它自己的 Claude Code 启动时读的 settings 文件（钩子记录）；守护进程也盯这些文件；与 `[claude] config_dir` / `CLAUDE_CONFIG_DIR` / `~/.claude` 不一致时 doctor 提醒。
- 重开队列记尝试次数，3 次失败放弃并记 `restart-failed` 事件；`--stale` 或抢占失败入队的条目，切换已生效后丢弃。
- shell 窗格里重开键入 `cd '<会话目录>' && claude --resume <id> --name=<名字> <白名单参数>`；仅写在原命令行前缀的环境变量不带上。
