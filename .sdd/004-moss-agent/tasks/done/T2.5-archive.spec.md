- arch_level: yes
- depends_on: [T2.4]
- release: 0.3.0 之后紧接着做，发 0.3.1（用户 2026-10-19）
- verify_layers: [unit, integration, e2e, ui]
- risk: migration
- mutations:

## 目标

不再用的会话自己收进「归档」，列表只留最近在用的。超过 30 天没动静的会话在每天整理时自动归档；归档随时能拿回来。想彻底清掉时，在 App 里点「清理」（单个或「全部清理」），消息发给 Moss，Moss 列出要删哪些、问你一句，你点了确认才删。

## Scope（YAGNI）

**In**
- registry 给会话加「已归档」标记（`archived_at_ms`），不新增状态；迁移只加一列，旧数据默认未归档
- `cc-moss archive <会话>` / `cc-moss unarchive <会话>`；`cc-moss ls` 默认不列已归档，`--archived` 只列归档
- 自动归档：守护进程每天整理时，把**没在运行**且 `last_active_at_ms` 超过 N 天的会话归档；N 由设置 `archive_after_days` 定（默认 30，0 = 关闭）。归档可撤回，不用问你，只在体检简报里说一句「归档了 5 个 30 天没用的会话」
- 删除（purge）：移除 registry 记录，并把该会话的对话记录文件（`transcript_path`）**移到废纸篓**，不直接抹掉，误删可从废纸篓找回
- 删除只走 Moss 的动作通道：`moss act purge <会话>`、`moss act purge-archived`，都要你点头（沿用 `[[confirm:]]`，按钮文字由守护进程按实际数量生成，比如「删除 12 个归档会话」）
- App：会话页底部有「已归档 (N)」入口，展开是归档列表，每行有「拿回来」和「清理」；列表顶上有「全部清理」。「清理」和「全部清理」都是给 Moss 发一句话，再切到 Moss 页看它确认
- Moss 的整理技能（moss-doctor）补上归档和清理的说明；快捷指令「整理会话」包含自动归档

**Out**
- 按项目或文件夹批量归档：没有需求证据
- 归档后压缩对话记录：节省的空间不大，还会让 `claude --resume` 失效
- 删除 Claude Code 在别处的数据（todos、shell 快照等）：先只处理对话记录本身，范围最清楚

## 行为口径

| 项 | 口径 | 用户确认 |
|----|------|---------|
| 多久算不活跃 | 30 天，可在设置里改；0 关闭自动归档 | 用户原话 30 天 |
| 正在跑的会话 | 永不自动归档；手动归档时先要结束它 | controller 默认 2026-10-19 |
| 删除的去处 | 对话记录移到废纸篓，不直接抹掉 | 用户 2026-10-19 |
| 归档会话被 `claude --resume` 接着用 | 自动取消归档，回到列表 | 用户 2026-10-19 |
| 搜索 | 默认也搜归档，结果放在「已归档」分组里 | controller 默认 2026-10-19 |

## 契约

- registry 新列 `archived_at_ms INTEGER NULL`（迁移）
- `moss act` 新动作 `purge <session>`、`purge-archived`；consent 必需
- 设置键 `archive_after_days`（整数，默认 30）
- `ls --json` 的每条多一个 `archived_at` 字段

## Success criteria

- [ ] 31 天没动、已结束的会话在一次整理后被归档，`ls` 里不再出现，`ls --archived` 里出现
      verify: `cargo test archive_after_idle_days`
- [ ] 正在跑的会话再老也不会被自动归档
      verify: `cargo test archive_skips_running_sessions`
- [ ] 没有你的确认，`purge` / `purge-archived` 什么都不删；确认后 registry 记录被移除、对话记录进了废纸篓
      verify: `cargo test purge_needs_your_yes purge_moves_transcripts_to_trash`
- [ ] `purge-archived` 只删归档里的会话
      verify: `cargo test purge_touches_only_archived`
- [ ] 归档后再用 `--resume` 接着用的会话会自动回到列表
      verify: `cargo test resumed_session_leaves_archive`
- [ ] App 的「已归档」分组：拿回来立即生效；「全部清理」给 Moss 发消息后切到 Moss 页
      verify: `swift.sh test` + 真机

## 风险与回退

- 删除是唯一不可撤回的动作，所以对话记录先进废纸篓，并且必须经过 consent
- 迁移只加一列可空字段，旧版本读新库时会忽略它
