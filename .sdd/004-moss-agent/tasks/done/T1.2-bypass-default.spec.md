## 目标

`cc-moss new` 和 App 的新会话表单起的会话，默认带 bypass，并且在 tmux 里不会卡在 Claude Code 首次 bypass 的警告框上；想要普通模式时 `cc-moss new --safe` 或设置里改默认。

## Scope（YAGNI）

**In**：
- 配置 `[claude] permission_mode = "bypass" | "default"`，缺省 `bypass`
- `new`：按 `permission_mode` 加 `--dangerously-skip-permissions`；`--safe` 本次不加，并去掉 `default_args` 里的权限参数（`--dangerously-skip-permissions`、`--permission-mode <值>`），只影响这一次；`default_args` / 命令行已带权限参数时不重复
- install（含 `cc-moss update` 后自动跑的 install）：`~/.claude/settings.json` 里没有 `skipDangerousModePermissionPrompt` 时写 `true`，并记下「是 cc-moss 写的」；uninstall 只撤销自己写的
- doctor：报告新会话的权限模式；`~/.claude/settings.json` 或 managed 设置里 `permissions.disableBypassPermissionsMode` 为 `"disable"` 时提示「管理策略禁用了 bypass，新会话按普通模式开」，`new` 此时不加 bypass
- App：设置 › 通用 › 新会话 加一行「直接放手干（bypass）」开关（读写 `cc-moss config` 的 `claude.permission_mode`）；新会话表单不变（参数由 CLI 决定）
- 文档：guide 中英、CHANGELOG

**Out**：
- 已在运行或断了的会话：不改它们的权限（找回沿用原启动参数，`launch_args.rs:17` 已能带回 bypass）
- 代答、PermissionRequest：T1.3
- 别名预设「trusted」（`AliasBoard.swift:23`）：保留，不删（老用户可能在用）

## 契约

- 配置键：`claude.permission_mode`，取值 `bypass` | `default`（protocol literal：CLI 与 App 共用）
- `~/.claude/settings.json` 受管键：`skipDangerousModePermissionPrompt: true`；「cc-moss 写的」记录在 `<state>/claude-settings-owned.json`（键名列表）

## 实施步骤（TDD 序）

1. 红：`config` 单测——缺省 `bypass`、`default` 可解析、非法值报错并指出键名
2. 红：`new` 命令行单测——默认带 bypass；`--safe` 不带；`default_args` 已含 `--dangerously-skip-permissions` 或 `--permission-mode` 时不重复；策略禁用时不带
3. 红：`settings_json` 单测——键不存在时写入并登记；用户本来就设了（true / false）时不动、不登记；uninstall 只删登记过的
4. 绿：实现；doctor 加一项；App 开关
5. e2e：临时 HOME + 独立 tmux socket + 假 claude，`cc-moss new x --detach` 后 pane 的命令行带 bypass；`--safe` 不带
6. 文档与 CHANGELOG
