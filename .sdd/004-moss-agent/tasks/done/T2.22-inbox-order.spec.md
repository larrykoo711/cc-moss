# T2.22 — 收件箱：你的消息先送、动态去旧并带时间（F60、F63）

- Source: 2026-11-09 真机：解卡后收件箱 196 条动态 + 2 条你的消息，你的排在最后；Moss 把几天前的动态当成今天（F63）。G1：动态 6 小时过期，超过 15 分钟带时间。
- arch_level: no
- depends_on: []
- risk: logic
- mutations:
  - 取件忽略 `from` 只按时间
  - 过期判断用 `>` 换成 `<`
  - 送出时不加时间前缀
  - 体检写入前不查待送

## Goal

积压时你的消息先送到 Moss；系统动态不刷屏、不过时、送出时让 Moss 知道它是什么时候发生的；每日体检不会因为卡住几天而连做几次。

## Scope

- `crates/moss-core/src/moss/inbox.rs` 取件：有 `from: you` 时先取最早的一条你的消息；你的斜杠命令保持现有特殊处理。
- 同文件取件时丢掉超过 6 小时的 `from: events` 动态（体检请求不算动态，见下）；写入时同一会话、同一种变化（做完了 / 断了）只留最新一条，旧的删掉。
- 送出动态时，发生时间早于 15 分钟的在正文前加时间（例如「[动态 · 3 小时前] proj-a 做完了」，中英各一套）。
- `crates/cc-moss/src/cmd/moss.rs` 每日体检：收件箱里已有一条没送出的体检请求时不再加。体检请求要能和普通动态区分（现在都是 `from: events`，需要加一个类型字段或单独的 `from`）。
- 不改你的消息内容，不丢你的任何消息。

## Success criteria

- [x] logic：收件箱里先有 10 条动态、后有 1 条你的消息时，下一条送出的是你的消息；之后动态按时间顺序。
      verify: `cargo test -p moss-core inbox_yours_first`
- [x] logic：超过 6 小时的动态在取件时被丢弃且不送出；6 小时内的照送；你的消息无论多旧都送。
      verify: `cargo test -p moss-core inbox_drops_stale_events`
- [x] logic：同一会话连续三条「做完了」写入后，收件箱里只剩最新一条；不同会话互不影响；「断了」与「做完了」分开计。
      verify: `cargo test -p cc-moss moss_events_coalesce_per_session`
- [x] logic：发生在 15 分钟以前的动态送出时带时间前缀，15 分钟内的不带；中英文案各有断言。
      verify: `cargo test -p moss-core inbox_event_age_prefix`
- [x] logic：收件箱里已有待送体检时，`daily_checkup` 到点不再写第二条；送出后第二天照常写。
      verify: `cargo test -p cc-moss daily_checkup_not_doubled`
