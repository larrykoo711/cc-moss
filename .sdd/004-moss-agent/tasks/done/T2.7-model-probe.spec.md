## 目标

在实现前，用隔离 Claude Code 与本机假 API 定下模型优先级，明确未验证边界，不把启动参数正确当作请求成功。

## Scope

In：临时 HOME/config/state、净化环境、本机 port0 API、假凭据、合成测试会话。
Out：生产渠道、真实凭据、真实会话或用户 tmux、自动重发用户消息、产品代码修改。

## 现状与锚点

- `crates/cc-moss/src/cmd/restart.rs:87` 仅删除旧模型参数，不显式添加新模型。
- `crates/cc-moss/src/cmd/restore.rs:426` 恢复回放旧参数。
- 官方文档与既有 2.1.303 探针不能替代 2.1.306 恢复请求验证；见 `notes/provider-model-recovery.md`。

## 行为口径

每个用例断言首个主对话请求模型、会话 ID 不变、历史可用；证据不足明确失败或未验证，禁止绕过。

## 契约

探针只绑定 127.0.0.1；假服务记录 model 和合成会话必要字段；不得输出认证值。

## 实施步骤

构造假 API → 创建模型 A 的测试会话 → 按矩阵恢复 → 断言 → 输出脱敏报告；同一问题最多三次尝试。

## Success criteria

- [x] e2e：顶层 model / env 固定模型 / 显式参数 / default / opus 映射五种恢复路径有真实请求断言。
      verify: `uv run --no-project --offline python -I scripts/provider-model-probe.py --claude "$(command -v claude)" --mode bare`
- [x] e2e：原 ID 与历史连续性被断言；配置无效或请求不符时脚本非零退出；自身子进程退出无残留。
      verify: `uv run --no-project --offline python -I scripts/provider-model-probe.py --claude "$(command -v claude)" --mode safe`

## Test cases

保存 A，顶层 B；保存 A，env B；env B + 参数 C；无固定默认 + default；opus + family B。

## Changed files

`scripts/provider-model-probe.py`；`reports/provider-model-probe.md`（由 controller 整理脱敏证据）。

## 风险与回退

隔离环境不完整会读到真实配置；必须清空继承环境并显式临时配置路径。失败时只终止自己启动的子进程。
