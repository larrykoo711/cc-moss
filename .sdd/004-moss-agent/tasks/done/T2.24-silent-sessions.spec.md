# T2.24 — 没说过话就退出的会话直接关掉（F62）

- Source: 2026-11-09 真机：一个没说过话就退出的会话被列为「断了」，找回报 `empty`，用户不知道它从哪来（`notes/round-0310-drivers.md` F62）。G1 假设 A5。
- arch_level: no
- depends_on: []
- risk: migration
- mutations:
  - 进程消失路径不应用规则
  - 判断「没说过话」只看 `last_prompt` 不看对话记录
  - 对账把说过话的行也关掉

## Goal

一个会话从没收到过你的任何一句话就退出了，不管从哪条路径退出，都直接关掉（不归档、不删任何文件），不再出现在可找回的列表里。升级后对账把现有的这类行一并关掉。

## Scope

- 判定「没说过话」：`last_prompt` 为空，且对话记录里没有任何你发的消息（对话记录不存在也算没有）。adopt 建的行 `last_prompt` 可能为空，必须看对话记录（`transcript.rs:223`）。
- 三条路径统一用这个判定：异常原因的 SessionEnd（`registry.rs:515-524`）、进程消失（`slot.rs:120-137` 的派生状态、`reconcile.rs:172-181`）、`release_process`（已有，`registry.rs:1381-1388`）。
- 对账（`reconcile`）每轮关掉已经是「断了」又满足判定的行；关掉时记一条事件（便于排查），不给 Moss 发「断了」的动态。
- 不碰正在运行的行，不碰归档的行。

## Success criteria

- [x] logic：没说过话的会话以异常原因 SessionEnd 退出后，状态为 `closed`；说过话的同样退出仍为 `interrupted`。
      verify: `cargo test -p moss-core silent_session_end_closes`
- [x] logic：没说过话的会话进程消失后，对账把它关掉；说过话的仍显示「断了」可找回。
      verify: `cargo test -p cc-moss reconcile_closes_silent_dead_sessions`
- [x] logic：`last_prompt` 为空但对话记录里有你的消息的行（adopt 情形）不被关掉。
      verify: `cargo test -p cc-moss reconcile_keeps_adopted_with_messages`
- [x] logic：现有登记表里已是「断了」且没说过话的行，升级后第一轮对账被关掉，不产生给 Moss 的动态。
      verify: `cargo test -p cc-moss reconcile_closes_existing_silent_rows`

## 实施记录

- commit：`fix(registry): close a session nobody spoke to when it exits`（哈希见 `git log`）。
- 判定 `registry::never_spoke`：`last_prompt` 为空，且这一行所有对话记录里都没有你打的字（`transcript::has_prompt`，从头读、遇到第一句就停；文件不存在算没有）。`silent` 再加上：未关闭、未归档、不是 Moss、不在 `restart`/`restore` 回来的途中。
- 三条路径：异常原因的 SessionEnd → `closed`（`ended` 事件带 `silent: true`）；进程消失 `record_lost_of`（对账与 Moss 侧共用）→ `close_if_silent`；`release_process` 改用 `never_spoke`。对账 `record_lost` 对「已是断了」（存的 `interrupted`，或存的 `running` 但进程没了）的行调用 `close_silent`，关掉时记 `ended`，不记 `interrupted`，所以不给 Moss 发「断了」。
- 测试：红（`silent_session_end_closes`：`Interrupted` ≠ `Closed`）→ 绿：
  - `cargo test -p moss-core silent_session_end_closes` ok
  - `cargo test -p cc-moss reconcile_closes_silent_dead_sessions` ok

## AMEND-1（2026-11-09，独立评审 #4–#6）

- 改了什么：
  - `never_spoke`：这一行没有记录任何对话记录路径时不算没说过话（同 `restore.rs` 的规则：没有路径什么也证明不了）；只有 `NotFound` 算「没有对话记录」，其他读取错误一律当作说过话。
  - `transcript::has_prompt` 返回 `io::Result<bool>`，并把你打的斜杠命令（`<command-name>`、`<command-message>`）和 `!` 命令（`<bash-input>`）算作说过话（`last_prompt` 的预览会滤掉它们）。
  - 有名字的行一律不当作没说过话关掉（保守）。
- 为什么：#4 没有路径或读不了被当成「空」会误关；#5 只打过斜杠命令的会话也是你用过的；#6 起过名字的会话是你特意留的。
