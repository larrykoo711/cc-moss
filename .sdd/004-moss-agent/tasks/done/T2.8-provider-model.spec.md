## 目标

把普通重开与应用当前渠道模型分开；即使旧会话无基线也能手动应用。保留会话ID与pane，忙碌延后，不重发用户任务，不宣称模型API已验证。

## Scope

In：模型解析与来源、JSON计划、显式重开/找回策略、队列持久化与取消、启动确认、相关双语guide。
Out：改变用户渠道设置、存凭据、生产探测、自动模型轮询或自动重放消息、Moss生命周期改造、发版。

## 行为口径

- 普通重开保留原选择；渠道应用显式唯一 `--model`；原会话ID与pane不变。
- 用户设置来源优先会话记录；项目/local覆盖不能静默忽略。无法确定来源或配置非法时拒绝应用并说明，不猜模型。
- 固定模型优先；其次明确顶层选择；别名依当前渠道family映射；无明确选择的default分支只在T2.7验证后启用。
- 无基线不等于已切换，标为unknown；仅配置可热读不宣称实际模型兼容。
- 队列保存操作策略，执行时重新解析当前配置；普通重开与渠道应用策略不可互相丢失。取消只撤销未执行队列，不杀进程。
- 成功必须等新SessionStart或明确返回starting；不验证生产API，不把命令提交当作模型切换成功。
- 不新增依赖，不记录任何认证值，不把任意配置值输出到JSON。

## 契约（2026-10-21 已冻结）

- `restart --provider-default [--stale] --json -- <id>`：显式按当前渠道模型重开。
- `restart --cancel --json -- <id>`：取消队列；不能与now/provider-default/stale同时用。
- `restore --provider-default --yes --json -- <id>`：显式按渠道模型找回；普通restore不改变既有策略。
- `ls --json` 新增可选 `provider_model` 对象：`{model: string|null, source: string, revision: string, uncertain: bool}`；只含安全模型数据；source表示实际解析来源，revision供App按本次配置确认，不能含凭据。
- `provider_restart` 保留旧兼容字段；`restart_queued`保留。
- `restart`结果兼容既有restarted/queued/refused，并支持 `starting`/`cancelled`；restarted仅确认新会话已启动，不表示API通过。

## AMEND 与裁决（2026-10-21）

项目/local含相关provider覆盖或已知自定义来源无法保真时明确拒绝，不因无关项目设置拒绝。无基线旧会话允许按当前默认配置显式应用，uncertain=true不阻止可解析目标。source枚举 env/settings/alias/default/unknown；revision含安全模型计划、host、provider键名集，不含认证值。队列重复明确请求采用最后策略；取消只撤未执行项，执行中refused/in-progress；显式渠道队列不因restart_reason=None丢弃。配置来源与实际启动CLAUDE_CONFIG_DIR保持一致。

## REVIEW-AMEND：选择策略与执行所有权（2026-10-21）

独立评审确认：最后成功响应的具体模型不能代表当前选择（例如opusplan运行时响应为sonnet，或用户刚选B尚未成功响应）。撤回以last_assistant_model覆盖普通重开选择的实现建议；普通恢复不得以观测值猜测并强制覆盖，显式渠道应用才指定解析目标。保留选择的验收不能用“最后响应模型相同”替代，无法观察的当前选择明确记录验证边界。

直接重开也必须参与统一的执行所有权，或以请求代次CAS撤销自己所属项；不能让较早直接重开完成时无条件删除后来明确请求。已经执行时后续操作应明确in-progress拒绝，而非返回queued后吞掉请求。增加opusplan、选择与观测不一致、直接执行与后续渠道应用竞态回归。
