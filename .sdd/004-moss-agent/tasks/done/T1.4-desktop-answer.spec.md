## 目标

会话停下来问你选择题（或 `--safe` 会话要权限）时，不用进终端：面板顶部有一张答题卡片，小莫或通知把你带过去，点选项或打字就答完了，会话照常往下走。你在终端里先答了，桌面上的卡片自己消失。会话「在等你输入」（不是选择题）时，也能在卡片里直接回一句。

## Scope（YAGNI）

**In**：
- 接手：App 运行期间每 60 秒调一次 `cc-moss ask take --name desktop`（设置里「替会话接住问题」关掉时不调）
- 读题：状态目录变化时（现有 FSEvents 监视）+ 打开面板时，跑 `cc-moss ask list --json` 解码（契约见 T1.3）
- 面板：顶部「有 N 个问题在等你」答题区，每题一张卡片（会话名、问题、选项）：
  - 单选：选项按钮，点了就答
  - 多选：复选 + 「答好了」
  - 自由输入：「自己写」展开输入框（Return 提交）
  - 权限（`--safe` 会话）：「允许」「不允许」，并显示要做的事（预览已脱敏）
  - 一次多题：逐题选完再提交
  - 答题走 `cc-moss ask answer <id> … --by desktop`；按退出码与输出区分「答好了 / 晚了一步 / 会话没在等」，后两种给一句说明后收起
- 提醒：新题按现有 `AlertRouter`（`AlertRouter.swift:50`）只去一处——小莫在场时由小莫冒泡（`PetBubble` 预留的 detail 区放选项，`PetBubble.swift:184-186`），否则发系统通知（点开面板定位到这道题）；同一题不重复提醒
- 撤回：题目从 `ask list` 消失（被终端答了、超时、会话结束）→ 卡片、小莫气泡、通知都撤掉
- 「在等你输入」：会话状态是 waiting 且不是选择题时，卡片区显示「它在等你」+ 输入框，提交走现有 `cc-moss send`
- 设置 › 通知（或通用）加「替会话接住问题」开关（读写 `cc-moss config` 的 `ask.enabled`）
- 离屏渲染：`--asks <demo.json>` 渲染面板答题区与小莫气泡的四种卡片；`--click` 探针点选后断言调用了 `ask answer`
- 文档：guide 中英「替会话接住问题」一节补上桌面部分；README 中英若列功能则加一句；官网 FAQ 若涉及则同步（事实与 guide 一致）；CHANGELOG

**Out**：
- Slack、路由与在场：T4.x
- 等待时长的设置项（只能手改 `ask.wait_secs`，guide 已写）
- 只关权限题的单独开关（T1.3 决定：整个关 `ask.enabled`）

## 实施步骤（TDD 序）

1. 红：MossKit 解码 `ask list --json`（含多题、多选、权限、缺字段、未知 schema）
2. 红：卡片状态机——选择 / 多选 / 自由输入 / 多题逐题 / 提交中 / 三种答题结果 / 撤回
3. 红：提醒路由——新题去一处、同题不重复、撤回时清掉
4. 红：心跳——运行中每 60 秒一次、开关关时不调
5. 绿：实现面板答题区、小莫 detail 区、通知、设置开关
6. 离屏渲染四种卡片（中英深浅）；`--click` 探针：点第二个选项 → 断言 `ask answer <id> --choice <label> --by desktop` 被调用（用可注入的命令执行器）
7. e2e：假 claude + 临时 HOME + 独立 tmux socket：起会话 → 假 claude 发 PreToolUse / PermissionRequest → App 模型（无界面，MossKit 层）答 → 假 claude 收到答案
8. 真机：controller 用真 claude 走一遍（按探针纪律：临时状态目录不适用——这里要验证真实链路，改为用户确认后在用户的真实环境里起一个 `--safe` 会话测；或用户自己测）
