## 设计合同

1. 共享typed预检错误至少区分config_source_unknown、config_source_unsupported、invalid_config_source、resume_preflight_failed；真实tmux启动失败才tmux_failed。不匹配错误英文字符串。
2. restore新增互斥--config-source default与--config-dir绝对目录，只允许一个明确目标，拒绝批量/歧义，与--provider-default互斥。--yes不选择来源。
3. Recorded默认保守拒绝；用户选择Default使用env -u，Directory验证绝对目录存在且无控制字符，独立argv传值。来源选择不能清空不可回放标记或绕过其他身份/路径/目标检查。
4. 仅改变本次恢复参数，不预写旧Snapshot，不修改任何全局设置；正常SessionStart可记录实际新来源。无选择与失败路径均零claim/launch，取消零命令。
5. App仅对单行unknown提供选择；来源hint原路径只提示，不从parent推自动选择。选择/确认绑定当前slot+session，换代/删除后拒绝旧回调。restoreAll不批量套来源、不同时弹多个目录选择器。
6. Moss不扩act自由参数/原consent，不让模型自动选；错误说明引导用户到面板或显式CLI。
7. 本机23条来源修复是用户单独授权的现有数据操作，不作为产品自动迁移机制；其余未知继续要求选择。

## 执行前条件与并发澄清（2026-10-22）

App一次性来源调用必须带require-unknown-config前置条件（仅与来源override合用）；后端以当前记录而非历史notice核验Unknown，否则config_source_changed，零claim/launch。普通CLI用户直接明确选源不附此条件时仍按其一次性意图处理。未新增ls字段，不把原错误提示当新来源证据。

恢复claim原子比较planned.provider_started原值，SQL IS处理NULL；来源在预检后变化也拒绝，不自动重试。hook先登记后保存来源的窗口由CAS保护，不改变正常hook顺序。测试用两个连接在lastActive不变时更新来源，断言旧claim失败；同值NULL及已知原值保持原行为。

App同slot/session重复打开、取消、目录picker回调均用独立token；执行前再次核身份/token，后端完成来源条件核验。选择目录本身不启动，确认才发命令。预检失败零claim/launch不适用于已经执行tmux启动尝试后返回的真实tmux失败，后者仍分类tmux_failed。
