# T2.15 — 恢复时保留全局配置来源

- Source: 2026-10-22 用户反馈恢复会话/mcp失效，随后明确「修复发版」。临时HOME真实Claude探针证明unset与explicit-default读取不同全局JSON。
- arch_level: yes

- risk: logic
- ui: no
- mutations: []

## 目标

restore/adopt/restart不能把原未设置CLAUDE_CONFIG_DIR变为显式默认目录，不移动或复制用户配置/凭据。启动来源与provider设置文件路径解耦。

## 设计与批准

用户已批准修复并发布。provider.settings_path把unset/explicit-default归一为同一路径，hook只保存路径，resume_argv无条件env赋值；已实测该赋值切换全局MCP配置。来源必须独立三态Unknown/Unset/Explicit(path)，在路径归一化和settings解析之前采集；settings坏或不存在也不丢来源。现有config/schema存储可扩安全字段，不存完整argv/配置正文/环境秘密。

## 行为合同

- Unset用env -u CLAUDE_CONFIG_DIR，即使tmux server带污染变量也清掉；Explicit原样验证回放，等于默认目录也不当unset。
- Unknown不得从settings路径反推，不自动猜默认。活进程可只读取该单一环境变量的精确来源以形成新证据，不能持久化或输出完整环境；无法可靠采集则在退出前拒绝。死会话未知来源明确拒绝并说明需选择来源，不能先终止再报错。
- 已被错误恢复并重新捕获为explicit的会话不自动改写，不复制/合并配置。用户可明确选择默认来源的修复操作若实现需独立显式参数，不能隐式套在普通恢复。
- provider_default只改模型不改启动配置来源；三入口复用builder且adopt在发信号前预检全部可回放性。
- MCP/settings CLI来源当前白名单丢弃不直接放开任意参数。新捕获至少保存安全的不可回放原因/存在标记并在副作用前明确拒绝，不能静默丢--mcp-config/strict/setting-sources/settings；仅保存参数名，不存内联JSON/凭据。若安全文件路径保真需另行审查，不借本轮克隆全环境。
- 旧快照反序列化兼容且Unknown，明确来源新记录跨持久化仍区分；reconcile不凭默认路径伪造来源。

## 边界

参数注入与秘密零落盘优先；不声称MCP服务连接可用，只证明读到原配置来源。真实修复/重开/安装另行授权；发版授权不含自动操作用户会话。

## 评审澄清（2026-10-22）

- 不可回放来源扫描必须区分参数边界和值；必需值恰为`--`不得截断后续真实MCP选项，值恰为选项名不得伪造来源。未知结构保守拒绝，不记录值或内联秘密。
- busy排队也属于用户可见写副作用：Unknown/不可回放来源在enqueue前拒绝，零待办，原进程不动。仅预检来源，不冻结动态目标模型；队列执行仍按当前配置解析模型。取消操作不因未知来源被阻止。
- 当前最小实现不采集活进程完整环境，不承诺可给历史Unknown补来源；明确拒绝并保留原会话。已记录Explicit不自动改成Unset。
