# T2.25 — 「信任此文件夹」默认选中 No 时也替 Moss 选 Yes（F64）

- Source: 2026-11-09 T2.20 探针截图：Claude Code 2.1.319 的「信任此文件夹」框默认选中「No, exit」；`reply::trust_prompt` 只认选中 Yes，新机器上 Moss 会停在这个框上且不报卡住。用户 2026-11-09：「信任文件夹那个也一起修，默认替它选 Yes」。
- arch_level: no
- depends_on: [T2.21]
- risk: logic
- mutations:
  - 选中项还是 No 时就按回车
  - 移动选择后不再核对就按回车
  - 信任窗口过后仍停在框上却不报卡住

## Goal

Moss 启动时遇到「信任此文件夹」框，不管默认选中的是 Yes 还是 No，守护进程都替它选 Yes 并确认；任何时候都不在 No 被选中时按回车。处理不了时（例如框的样子变了、移动选择后仍不是 Yes）按 T2.21 报告卡住。

## Scope

- `crates/moss-core/src/moss/reply.rs`：识别信任框本身，与「当前选中哪一项」分开判断。
- `crates/cc-moss/src/cmd/moss.rs` `accept_trust`：选中 Yes → 回车（原行为）；选中 No → 发一次方向键，重新抓窗格，确认选中 Yes 后才回车；核对不通过就不按回车。只作用于 Moss 自己的 tmux（`cc-moss-moss`）。
- 信任窗口（`TRUST_WINDOW`，60 秒）过后仍停在信任框上：按 T2.21 写卡住标记，`kind` 新增 `trust_folder`，App 与 doctor 文案中英各一。
- 只改 Moss，不碰普通会话。

## Success criteria

- [ ] logic：信任框文本两种默认选中（Yes / No）都识别为信任框，并正确读出当前选中项；bypass 警告、普通输入框不识别为信任框。
      verify: `cargo test -p moss-core trust_prompt_selection`
- [ ] logic：用伪造窗格驱动 `accept_trust`：选中 No 时先发方向键、核对变成 Yes 后才发回车；方向键后仍是 No 时不发回车；选中 Yes 时直接回车。断言发出的按键序列。
      verify: `cargo test -p cc-moss accept_trust_moves_to_yes`
- [ ] logic：信任窗口过后仍在信任框上时，`moss status --json` 报 `activity: "blocked"`、`blocked.kind: "trust_folder"`。
      verify: `cargo test -p cc-moss moss_status_reports_trust_blocked`

信任框文本用 T2.20 探针实抓的 2.1.319 原文作测试夹具；方向键的具体键名以实抓到的交互为准，探针可在隔离 tmux 里复跑验证一次，结果补进 `reports/moss-bypass-probe.md`。
