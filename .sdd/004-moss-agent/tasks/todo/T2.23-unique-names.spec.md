# T2.23 — 同名会话自动加编号（F61）

- Source: 2026-11-09 真机：Claude Code 后台以 `--fork-session` 分出的新会话继承原名，面板两行 `proj-a`；分叉记录里 Claude Code 用新编号写了原名（`notes/round-0310-design.md` F61）。
- arch_level: no
- depends_on: []
- risk: logic
- mutations:
  - 新建行写名字时不查重
  - 补名覆盖已有的名字
  - 查重把自己这一行也算进去

## Goal

一个会话的名字和另一个还开着（未关闭、未归档）的会话重名时，自动改成 `名字-2`、`名字-3`，和 `cc-moss new` 的规则一样；之后从对话记录补名不会把它改回去。原会话不动。

## Scope

- `crates/moss-core/src/registry.rs`：钩子新建行写名（`:416-418`）、从对话记录补名（`hook.rs:247-265` 调用处与 `backfill_names` `:704-739`）统一走一个「对照其他开着的行取唯一名」的函数，复用 `naming::unique`（`naming.rs:144-153`）。
- 只在名字**第一次写入**或从空变有时去重；用户主动改名（`rename`）撞名时沿用现有提示，不偷偷改用户亲手起的名字。
- 同一会话编号续接（`/resume` 同编号、F57 的后台接手同编号）不受影响：查重时排除自己这一行。
- 去重后的名字同步到 tmux 名的现有逻辑照旧（分叉行没有 tmux 位置时只改登记表）。

## Success criteria

- [ ] logic：已有开着的 `proj-a` 时，新编号的行从钩子拿到名字 `proj-a`，登记为 `proj-a-2`；再来一个得 `proj-a-3`；原来那行仍是 `proj-a`。
      verify: `cargo test -p moss-core registry_unique_name_on_insert`
- [ ] logic：`proj-a-2` 那行之后再收到对话记录里的标题 `proj-a`，补名不改回；名字为空的行补名时同样去重。
      verify: `cargo test -p moss-core registry_backfill_keeps_unique_name`
- [ ] logic：已关闭或已归档的同名行不算占用；同一编号的行再次登记（续接）保持原名不加编号。
      verify: `cargo test -p moss-core registry_unique_name_ignores_closed_and_self`
