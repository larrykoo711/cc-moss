## 目标

用户执行一次 `cc-moss setup`，看到将要对 `~/.claude/settings.json` 做的改动（diff），确认后写入四个钩子；
之后新开的 Claude Code 会话自动登记到 cc-moss。`cc-moss setup --uninstall` 把文件恢复到安装前的样子，
不碰用户自己配置的任何东西。

## Scope（YAGNI）

**In**
- `moss-core::settings_json`：纯函数 `install(doc, exe) -> doc`、`uninstall(doc) -> doc`、`is_ours(entry)`，
  以及按 Claude Code 的格式序列化（2 空格缩进、保留键顺序、非 ASCII 不转义、末尾换行）
- `cc-moss setup [--dry-run] [--yes] [--uninstall] [--settings <path>]`：
  读文件 → 计算新内容 → 无变化就报告「已是最新」→ 有变化就打印统一 diff → 确认（`--yes` 跳过；非 TTY 且无
  `--yes` 时拒绝并说明）→ 写备份 `settings.json.cc-moss-<UTC时间戳>.bak` → 原子写入（临时文件 + rename）
- 钩子命令用 setup 时 `cc-moss` 可执行文件的绝对路径，路径含空格时加引号
- 识别「我们的条目」：`command` 去掉引号后匹配 `(^|/)cc-moss hook (session-start|user-prompt-submit|stop|session-end)$`。
  这样升级（路径变了）时能替换旧条目，而不是叠加

**Out**
- zsh 集成 → T2.1（PLAN 2026-10-15 变更）
- 项目级 `.claude/settings.json`：只装用户级，钩子对所有项目生效（DESIGN §2）
- 自动检测「Claude Code 未安装」：文件不存在时照常创建，Claude Code 首次启动会读到

## 现状与锚点（证据）

| 锚点 | 证据 | 动作 |
|------|------|------|
| settings.json 的序列化格式 = `JSON.stringify(x, null, 2) + "\n"` | 2026-10-15 对本机 `~/.claude/settings.json` 实测：Python `json.dumps(indent=2, ensure_ascii=False) + "\n"` 与原文逐字节一致 | 按此格式写回 |
| 钩子条目形状 `{"hooks": {"<Event>": [{"matcher"?, "hooks": [{"type":"command","command":…, "timeout"?}]}]}}` | 本机另一项目的 settings.json 里的 PostToolUse 条目 | 新建 |
| 钩子命令字面量 `cc-moss hook <session-start\|user-prompt-submit\|stop\|session-end>` | T1.1 spec「契约」；`crates/moss-core/src/agent/mod.rs` 的 `HookKind::cli_name` | 复用 |
| 事件名映射：SessionStart / UserPromptSubmit / Stop / SessionEnd | `notes/hook-probe.md` 探针所用的 settings | 新建 |

## 行为口径

| 项 | 口径 | 用户确认 |
|----|------|---------|
| 写入前必须展示 diff 并确认 | 是；`--yes` 跳过 | 2026-10-15（DESIGN §10 Q3） |
| 备份 | 每次实际写入都留一份带时间戳的备份 | 2026-10-15（DESIGN §10 Q3） |
| 条目参数 | 不写 `matcher`（匹配所有来源）；`timeout: 10`（秒），防止钩子异常拖住 Claude | 自决（默认值：最小必要） |

## 契约

- 写入的条目（每个事件一条，`<exe>` 为绝对路径）：
  `{"hooks": [{"type": "command", "command": "<exe> hook session-start", "timeout": 10}]}`
- 识别规则见 Scope；T1.1 的 `HookKind::cli_name` 是字面量的唯一来源

## Success criteria

- [ ] 文件不存在、为 `{}`、已有其他键时，install 都只增加四个事件下的 cc-moss 条目，其他键与顺序不变（unit）
      verify: `cargo test -p moss-core --test settings_json install_preserves_everything_else`
- [ ] 同一事件下已有用户自己的钩子时，两者并存（unit）
      verify: `cargo test -p moss-core --test settings_json keeps_foreign_hooks_on_same_event`
- [ ] 重复 install 无变化；旧路径的 cc-moss 条目被替换成新路径，不叠加（unit）
      verify: `cargo test -p moss-core --test settings_json install_is_idempotent_and_upgrades_path`
- [ ] uninstall 只移除 cc-moss 条目；移除后空掉的事件数组和 `hooks` 键，恢复到安装前的形状（unit）
      verify: `cargo test -p moss-core --test settings_json uninstall_only_removes_ours`
- [ ] 对 Claude Code 格式的文件，install 再 uninstall 后与原文件逐字节一致（integration）
      verify: `cargo test -p cc-moss --test setup_cli install_then_uninstall_is_byte_identical`
- [ ] 原文件不是合法 JSON 时拒绝写入、退出码非零、原文件不变（integration，错误路径）
      verify: `cargo test -p cc-moss --test setup_cli invalid_settings_refuses_to_write`
- [ ] 非 TTY 且没有 `--yes` 时不写入并提示用 `--yes`；`--dry-run` 只打印 diff 不写（integration，错误路径）
      verify: `cargo test -p cc-moss --test setup_cli requires_confirmation_or_yes`
- [ ] 实际写入时生成备份，内容等于写入前的原文件（integration）
      verify: `cargo test -p cc-moss --test setup_cli writes_backup_before_change`
- [ ] L2 全绿
      verify: `cargo fmt --all --check && cargo clippy --all-targets -- -D warnings && cargo test --all`
