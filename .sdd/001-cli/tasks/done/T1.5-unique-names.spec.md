# T1.5-unique-names — 会话名唯一：同名即进入或恢复，不再新建

- Source: 用户 2026-10-16：「不可能开第二个同名会话的，要确保名称唯一」；`mycc xxxx` 重名时的处理按 controller 建议执行（同日对话）
- arch_level: no
- depends_on: [T1.3, T1.4]
- verify_layers: [unit, integration, e2e]
- risk: logic
- mutations:
  - point: 同名会话在运行时 `new` 仍新建  red: unique_names_e2e::new_enters_running_session_with_same_name
  - point: 同名会话已中断时 `new` 不恢复而是新建  red: unique_names_e2e::new_restores_interrupted_session_with_same_name

## 目标

一个名字在任何时刻只对应一个未关闭的会话。`cc-moss new xxxx`（即 `mycc xxxx`）遇到同名：在运行就进入它，
已中断就提示恢复并用原会话 id 拉回来，只有已关闭或不存在时才新建。会话里 `/rename` 成别人的名字时，钩子提醒改名。

## Scope（YAGNI）

**In**
- `cc-moss new [name]` 先查未关闭（有效状态 running / interrupted）的同名会话：
  - 运行中：打印「已在运行，进入」并 attach（`--detach` 时只打印）
  - 已中断：TTY 下问「恢复它？[Y/n]」（默认是）；`--yes` 直接恢复；非 TTY 且无 `--yes` 报错并提示 `cc-moss restore <name>`。
    恢复走 T1.4 的同一套逻辑（规划、认领、拉起、记录进程），恢复后 attach
  - 已中断但是空会话（从没发过消息，F8）：没有可恢复的内容，直接关掉它并新建
  - 已中断但不可恢复（目录不存在等）：报错说明原因，提示 `cc-moss close <name>`
  - 多个同名未关闭会话（历史遗留或 `/rename` 造成）：报错并列出 id 前缀
- `/rename` 撞名：UserPromptSubmit 发现本会话的新名字与另一个未关闭会话相同时，stdout 输出
  `{"systemMessage": "cc-moss: another session is already named …"}`；tmux 名照旧按 T1.3 规则加后缀
- 恢复逻辑抽成可复用的函数，`restore` 命令与 `new` 共用（DRY）

**Out**
- 阻止 `/rename`：Claude Code 没有提供拦截改名的入口（F3），只能提醒
- 已关闭的同名会话：不参与唯一性（用户已主动放弃它）

## 行为口径

| 项 | 口径 | 用户确认 |
|----|------|---------|
| 同名在运行 | 进入，不新建 | 2026-10-16 |
| 同名已中断 | 提示恢复，默认是 | 2026-10-16 |
| 第二个同名会话 | 不允许，没有 `--new` | 2026-10-16（用户原话） |
| 已关闭的同名 | 不算占用 | 自决（默认值：close 的语义就是放弃） |
