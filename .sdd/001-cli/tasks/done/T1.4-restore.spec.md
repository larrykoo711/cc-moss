## 目标

机器重启之后，执行一条 `cc-moss restore`：列出意外中断的会话（名字、备注、目录、最后活动时间），确认后把每个会话
按原名字、原目录、原启动参数，用 `/clear` 之后的最新会话 id，拉回各自的 tmux 会话里，对话接着进行。另外提供
`note` 记下「停在哪 / 在等什么」，`close` 把不想恢复的会话移出候选，`attach` 直接跳到某个会话。

## Scope（YAGNI）

**In**
- `cc-moss restore [--yes] [--dry-run] [name…]`：
  1. 候选 = 有效状态为 interrupted 的槽位；给了名字就只取匹配的
  2. 逐个检查：会话记录文件（槽位当前 id 的 `transcript_path`）记录过却不存在 → 标为「空会话」跳过（F8）；
     工作目录不存在 → 跳过并说明；60 秒内已发起过恢复且尚未收到 SessionStart → 标为「恢复中」跳过
  3. 打印候选表；非 TTY 且没有 `--yes` 时拒绝；TTY 下问一次 `[y/N]`（全部或全不，逐个挑选用名字参数）
  4. 每个会话：`tmux new-session -d -s <唯一名> -c <cwd> <claude> --resume <当前 id> -n <name> <launch_args>`；
     写入 `restore_started_at`；最后打印 `cc-moss attach <name>` 提示
- `cc-moss attach <name>`：跳到该会话所在的 tmux 会话（在 tmux 内 `switch-client`，否则 `attach-session`）
- `cc-moss close <name>…`：标为 closed（`end_reason = closed-by-user`），不再出现在恢复候选里
- `cc-moss note <name> [--goal G] [--state S] [文本] [--clear]`：写入或清空备注；`ls` 的文本输出增加 NOTE 列
  （显示 state，没有就显示 note），`ls --json` 已有 `notes` 字段
- 名字解析（以上四个命令共用）：先按 Claude 会话名精确匹配，再按 tmux 会话名，再按 session id 前缀（≥ 6 位）；
  多个匹配时报错并列出候选
- 确认逻辑从 `setup.rs` 抽到 `cmd/confirm.rs` 共用（DRY）
- 登记表 schema 增加 `restore_started_at` 列（v1 尚未发布，直接改 v1 的建表语句）

**Out**
- 开机自动恢复（launchd / systemd）：R8，留待后续
- 恢复时逐个交互勾选（多选界面）：放 T2.1 选择器的 Interrupted 标签页；本任务用名字参数挑选
- 跨机器恢复：会话记录在本机

## 契约

- 恢复命令：`<claude> --resume <session_id> [--name=<name>] <launch_args…>`（未命名的槽位不传名字；`--name=` 写法防止以 `-` 开头的名字被当成参数），`<claude>` 默认 `claude`，可用
  `CC_MOSS_CLAUDE_BIN` 覆盖（测试用，与 `new` 一致）
- `close` 写入的 `end_reason` 字面量 `closed-by-user`

## 风险与回退

- **重复恢复**（同一会话跑两份）：三道防线——只恢复「进程确认已死」的槽位（T1.1 的严格身份判定）、60 秒恢复中保护、
  恢复前列表确认
- **恢复到错误的对话**：恢复命令只用槽位的当前 id（e2e 覆盖 /clear 之后的情形）
- 回退：恢复只是新建 tmux 会话，不改任何已有会话；不满意直接退出 claude 即可
