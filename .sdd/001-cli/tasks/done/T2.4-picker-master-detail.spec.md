# T2.4-picker-master-detail — 选择器重新设计：按项目分组的单行列表 + 右侧详情卡片

- Source: 用户 2026-10-16 走查 T2.3（附截图）：「还是不够易用和精美，且下方的表格一大片，眼睛都看花了，还是不够给 C 端用户使用的标准，好好重新设计 UIUX」；同日在两个方案中选定「左列表右详情」
- arch_level: no
- depends_on: [T2.3]
- verify_layers: [unit, e2e]
- risk: ui
- mutations:
  - point: 列表按状态分组而不是按项目  red: pick::app::tests::groups_by_project
  - point: 详情卡片不跟随选中项  red: pick::ui::tests::detail_follows_selection

## 问题诊断（T2.3 截图）

- 重复：10 个会话里 8 个同目录，路径重复 8 次；`tmux` 标签重复 10 次；页头 `0 working · 0 waiting`
- 没有层次：每行同字重、同高度，两行一组，整屏是均匀的一片
- 细节铺满：所有会话的全部信息同时展示，而用户一次只看一个

## 设计原则

1. 按项目（目录）分组，目录只写一次——也消除了「按目录进入有歧义」
2. 列表每个会话一行：状态点、名字、时间
3. 细节只给选中的那一个，放在右侧卡片
4. 没有的不显示：0 计数、`tmux` 标签、重复路径

## Scope

**In**
- 布局：页头一行（`◉ cc-moss` 与右侧概要，只显示非零项）→ 搜索行（`⌕` 占位、匹配数、细分隔线）→ 主体左右分栏
  （左列表约 40%、右详情卡片，中间一条细竖线）→ 底部一行按键提示
- 左列表：项目标题（目录名，同名时用缩写路径）+ 会话行（状态点 · 名字 · 右对齐短时间 `1m`/`3h`/`2d`）；
  项目按其最近活动排序，会话按最近活动排序；末尾 `+ New session here`（有搜索词时 `+ New session "<词>"`）
- 状态点：Working 橙色动画、Waiting 琥珀 `●`、Interrupted 红 `↺`、普通 tmux 会话灰 `○`
- 右详情卡片：名字（粗体）、状态一行（彩点 + 文字 + 多久前）、Note、Last message（自动换行）、目录全路径、
  可做的操作（`↵ Open` / `↵ Restore` / `→ More`）；普通 tmux 会话写明「Not a Claude Code session」；
  `+ New session` 写明会在哪个目录启动
- 窄终端（< 90 列）：不分栏，详情卡片放到列表下方
- 菜单、确认、写备注的弹框沿用 T2.3 的交互，位置放到详情卡片里

**Out**：主题切换、自定义布局（YAGNI）
