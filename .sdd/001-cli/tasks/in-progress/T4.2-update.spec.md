  「我们要先做升级功能，赶在 0.1.0 首次发布就带上」（不带上的话，装了 0.1.0 的人永远收不到之后的新版提醒）

## 现状（2026-10-16 实读）

- 没有任何版本检查或升级能力；`--version` 读 `CARGO_PKG_VERSION`
- 发布产物（release.yml）：`cc-moss-v<版本>-<target>.tar.gz` 与 `.sha256`，四个 target：
  `aarch64-apple-darwin`、`x86_64-apple-darwin`、`x86_64-unknown-linux-musl`、`aarch64-unknown-linux-musl`；
  tarball 里有一个顶层目录 `cc-moss-v<版本>-<target>/`，内含 `cc-moss`
- 三种安装方式：Homebrew（`larrykoo711/tap/cc-moss`）、Release 二进制、`cargo install --git`
- `install` 已经在用 `curl` 下载 starship 安装器（先下载后执行，`--proto '=https' --tlsv1.2`）

## 设计（已拍板：联网检查默认开启、可一键关闭）

- **查最新版本**：`curl -fsSI --proto '=https' --tlsv1.2 --max-time 3 https://github.com/larrykoo711/cc-moss/releases/latest`，
  取 `location:` 头里的 `/tag/vX.Y.Z`（不走 API，没有频率限制；不发送任何本机信息）。没有 curl、超时、离线 → 静默放弃。
  带 `-` 的预发布版本不算新版本
- **缓存**：状态目录下 `update.json`（`checked_at`、`latest`），24 小时内不重复检查
- **何时检查**：只在打开选择器（后台线程，不阻塞界面）、`cc-moss update`、`cc-moss doctor` 时；**钩子、`ls --json` 等脚本路径永不联网**
- **关闭**：配置 `[update] check = false` 或环境变量 `CC_MOSS_NO_UPDATE_CHECK=1`；关闭后选择器与 doctor 都不联网，`cc-moss update` 仍可手动用
- **选择器提醒**：已知有新版本时，页头显示一行醒目提示（中英），列表最上方出现一项「升级到 X.Y.Z」，回车后退出选择器、
  进入 `cc-moss update` 的确认流程；不需要记任何快捷键
- **`cc-moss update [--check] [--yes]`**：立即检查（忽略缓存）→ 显示当前版本、新版本、发布页链接 → 确认后按安装方式升级：
  - Homebrew（当前程序的真实路径在 brew 的 Cellar 下）：`brew upgrade larrykoo711/tap/cc-moss`
  - cargo（在 `~/.cargo/bin`）：`cargo install --locked --git https://github.com/larrykoo711/cc-moss --tag vX.Y.Z cc-moss`
  - 其他（Release 二进制）：下载对应 target 的 tarball 与 `.sha256` → 校验 → 解出 `cc-moss` → 先 `--version` 自检 →
    同目录临时文件原子替换当前程序（保留权限）；目录不可写时说明原因并给出手动命令，不用 sudo
  - `--check` 只报告不升级；已是最新时友好地说一声；`--yes` 跳过确认（脚本用）
- **doctor**：多一行「版本」：已是最新 ✓；有新版本 !（→ `cc-moss update`）；关闭了检查则显示跳过
- 测试全部离线：`CC_MOSS_RELEASES_URL` 覆盖发布地址，测试用 PATH 上的桩 `curl` / `brew` / `cargo` 记录调用、返回夹具

## Scope

**In**：上述版本检查、缓存、选择器提醒、`update` 命令三种安装方式、doctor 版本行、配置与环境变量开关、README 与 CHANGELOG（中英）、
隐私一节如实写明联网检查
**Out**：后台自动静默升级（必须确认）；Windows；签名校验（先用 sha256）
